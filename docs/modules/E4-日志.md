## 1. 职责与边界

- 为后台、弹窗、设置页、页面注入提供**唯一的日志入口**：级别过滤、统一格式、脱敏截断、控制台输出。
- 只输出到当前上下文的浏览器控制台；**不写 `storage`、不走消息、不上报、不导出**。
- 是纯模块：不依赖 E2、不读写浏览器存储，可被 content 内联。
- 未调用 `initLogging` 前保持静默；入口必须在注册监听器与连接后台之前初始化，避免模块导入阶段或测试产生输出。
- 不承载业务：不判断任务状态、不读密钥、不读页面正文、不发翻译请求。
- 日志失败不影响业务：控制台异常、序列化失败、全局异常捕获器异常都必须被吞掉。

## 2. 等级

| 内部值 | UI 文案 | 数值 | 输出方法 | DevTools 级别 | 默认可见 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| `debug` | 详细 | 10 | `console.debug()` | Verbose | 否，需勾选 Verbose |
| `info` | 信息 | 20 | `console.info()` | Info | 是 |
| `warn` | 警告 | 30 | `console.warn()` | Warning | 是 |
| `error` | 错误 | 40 | `console.error()` | Error | 是 |
| `off` | 关闭 | 100 | 不输出 | 无对应项 | — |

- 默认 `info`。
- 阈值：记录级别数值 ≥ 设置级别数值才输出；`off` 恒不输出。
- 非法设置值归一为 `info`；未知记录级别按 `info` 处理或丢弃，不能导致抛错。
- 不自造 `trace` 等 DevTools 没有对应过滤器的级别；最细一级就是 `debug`（Verbose）。
- DevTools 的 Log Levels 是第二层视图过滤；扩展设置决定是否调用 `console.*`，两者不冲突。

## 3. 接口

```js
initLogging({ context, level = 'info', sessionId, version, captureErrors = false });
setLogLevel(level);
getLogLevel();
createLogger(scope, { traceId } = {});
newTraceId();
resetLogging(); // 测试用
```

### 3.1 初始化

```js
initLogging({
  context: 'content',        // background | popup | options | content
  level: 'info',             // 初始级别；入口可先用默认值，随后从设置更新
  sessionId: undefined,      // 不传则自动生成；测试可注入固定值
  version: '0.1.0',          // 扩展版本，用于 logger.ready
  origin: undefined,         // 页面注入传 location.origin；用于 ready 与全局异常
  captureErrors: true,       // 是否安装全局异常捕获
});
```

- `origin` 只用于 `logger.ready` 与全局异常，不逐行打印；其它上下文可不传。

- 入口在注册监听器、连接后台之前调用。
- `initLogging` 可重复调用；后一次覆盖上下文、级别、版本；`sessionId` 不传时保留原值。
- 全局异常捕获只安装一次；重复调用不重复绑定。
- 版本读取失败（如 `chrome.runtime.getManifest` 不可用）时省略 `version`，不阻断初始化。

### 3.2 记录

```js
const log = createLogger('A2');
log.info('gateway.connect', '网关已连接', { tabId: 12 });
log.warn('batch.reject', '批次被拒绝', { reason: 'TEXT_TOO_LONG' });
log.error('engine.openai.error', 'OpenAI 兼容接口调用失败', { preset: 'deepseek', code: 'AUTH' }, error);

const traced = log.withTrace(traceId);
traced.info('batch.start', '开始处理批次', { items: 3 });
```

- `event`：稳定点分小写事件名，如 `gateway.connect`；已使用的事件不随意改名。
- `message`：中文短句，不把动态数据拼进正文。
- `data`：可选，浅层对象；按第 5 节脱敏、截断。
- `error`：可选，`Error` 或 `{ name, message, code?, reason?, stack? }`。
- `withTrace(traceId)` 返回同一 `scope` 的新 logger；不修改原 logger。

### 3.3 `traceId`

- `newTraceId()`：`t-<base36 时间>-<随机短串>`；非空、≤ 64。
- 入口生成，随命令消息传递，日志绑定；不参与业务判断。
- 无效 `traceId` 忽略，不阻断请求；日志中不输出空 `[trace:]`。

## 4. 记录结构与格式

### 4.1 字段

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `ts` | 是 | 毫秒时间戳 |
| `level` | 是 | `debug` / `info` / `warn` / `error` |
| `ctx` | 是 | `background` / `popup` / `options` / `content` |
| `scope` | 是 | 模块号，如 `A1` / `A2` / `D4` / `C1` / `E4` |
| `event` | 是 | 稳定事件名 |
| `message` | 是 | 中文短句 |
| `data` | 否 | 脱敏后的浅层对象 |
| `err` | 否 | `{ name, message, code?, reason?, stack? }` |
| `traceId` | 否 | ≤ 64 |
| `sessionId` | 是 | 当前上下文实例会话 ID |

### 4.2 输出格式

```text
[SimpleTrans][2026-11-15 10:32:15.123][bg][A2][INFO] gateway.connect 网关已连接 {"data":{"tabId":12}}
[SimpleTrans][2026-11-15 10:32:16.456][content][D4][DEBUG] bridge.heartbeat 心跳正常 {"data":{"count":3,"rtt":42}}
[SimpleTrans][2026-11-15 10:32:20.789][options][E4][ERROR][trace:t-m8x2k1-a9f3] global.error 未捕获异常 {"data":{"origin":"https://example.com"},"error":{"name":"Error","message":"…"}}
```

- 时间用本地时区，格式 `YYYY-MM-DD HH:mm:ss.SSS`。
- 上下文缩写：`background`→`bg`，`popup`→`popup`，`options`→`options`，`content`→`content`。
- 级别大写：`DEBUG` / `INFO` / `WARN` / `ERROR`。
- `traceId` 存在时追加 `[trace:…]`；`sessionId` 不逐行打印，只在 `logger.ready` 中打印。
- `data` 为单行 JSON；`err` 的栈另起行并缩进，便于复制。
- 启动横幅：

```text
[SimpleTrans][2026-11-15 10:32:10.001][bg][A][INFO] logger.ready 日志已启动 {"data":{"context":"background","level":"info","sessionId":"...","version":"0.1.0"}}
```

### 4.3 上下文与 scope

| `ctx` | 运行位置 | 控制台位置 |
| ---- | ---- | ---- |
| `background` | Service Worker | `chrome://extensions` → Service Worker → 检查 |
| `popup` | 工具栏弹窗 | 弹窗右键 → 检查 |
| `options` | 设置页 | 设置页右键 → 检查 |
| `content` | 页面注入 | 网页 DevTools → Console |

`scope` 用架构模块号：A1/A2/A3/A4、B1/B2、C1–C5、D1–D5、E1–E4。新增模块先有编号再使用。

## 5. 脱敏与截断

| 项 | 规则 |
| ---- | ---- |
| 敏感字段名 | `/key|token|secret|auth|pass|credential/i` → `[redacted]` |
| 完整 URL | 字符串中的 `http(s)://host/path?query` → `scheme://host[:port]` |
| 字符串 | 最长 200 字符，超出加 `…` |
| 数组 | 最多 20 项，超出加 `…(+N)` |
| 对象 | 最多 20 个键、深度 2（数组不计深度）；超出用 `[truncated]` |
| 数据 JSON | 单条最多 4 KB；超出丢弃后续字段并标记 |
| 错误栈 | 最多 2000 字符 |
| 不可序列化 | 循环引用、`BigInt`、函数、Symbol 转为字符串标记，不抛错 |

禁止记录：

- 密钥、`Authorization`、`apiKey`、请求头/请求体；
- 页面正文与译文、节点文本、用户输入原文、上下文、来源域名、缓存 key 哈希、提示词；
- 完整 URL（只保留来源）、查询串、cookie；
- 翻译服务原始错误报文（只保留统一错误码与安全提示）。

共享源码不得出现冒烟 S5 禁止的字面量；脱敏使用通用正则，不写密钥前缀。

## 6. 全局异常

- 入口调用 `initLogging({ captureErrors: true })` 或 `installGlobalErrorHandlers()`。
- 后台：`globalThis.addEventListener('error' | 'unhandledrejection', …)`。
- 弹窗/设置页：`window.addEventListener(…)`。
- 页面注入：`window.addEventListener(…)`；只记录扩展自身脚本：
  - `error`：`event.filename` 以 `chrome.runtime.getURL('')` 开头；
  - `unhandledrejection`：`reason.stack` 或 `reason.message` 含扩展 URL。
- 记录：

```text
[SimpleTrans][…][content][E4][ERROR] global.error 未捕获异常 {"data":{"origin":"https://example.com","filename":"chrome-extension://…/content.js","lineno":12,"colno":34},"error":{"name":"Error","message":"…"}}
```

- 捕获器自身 try/catch；日志失败不再次抛错。
- **取消是例外**：`unhandledrejection` 的 reason 为 `AbortError`（`name === 'AbortError'` 或 `code === 20`）时，视为用户/请求取消：
  - 记录 `global.abort`，级别 `info`，消息「操作已取消」，只带来源与名称，不输出栈；
  - 调用 `event.preventDefault()`，阻止浏览器把已预期的取消打印成红色未处理错误；
  - 其它未处理拒绝仍记 `global.unhandledrejection`（error），不调用 `preventDefault()`。
- 页面注入不记录网页自身脚本错误，避免噪声与隐私风险。

## 7. 级别分发

```text
设置页 C1 ──写──→ storage.sync settings.logLevel
                        │ storage.onChanged
                        ▼
                     后台服务（更新自身 logger）
页面注入 ──ST_PING──→ 后台 ──ST_PONG──→ 页面注入
                        └──ST_LOG_CONFIG { level }（每连接一次）
页面注入 ── setLogLevel ──→ 后续日志按新级别输出
```

- 弹窗/设置页打开时读设置；设置页保存后立即更新自身。
- 后台启动读设置；`storage.onChanged` 只更新自身，不广播。
- 页面注入默认 `info`；连接建立后收到一次 `ST_LOG_CONFIG`；刷新/重连后生效。收到配置前可能输出少量连接状态日志；`logger.ready` 在收到配置后输出，`off` 时不会出现。
- 后台、弹窗、设置页在读取设置完成前也使用默认 `info`；读取完成后按设置过滤。
- 不做实时推送；设置页说明文字必须提示。

- `page.submit` / `page.scroll` / `page.error` 只记段数、字符数、错误码与耗时，不含原文。

- `scan.*` 记段落数、跳过数与耗时，同样不含页面文本。
- D1 不直接打印日志：扫描时由 D5 注入 E4 日志入口，事件名仍按 `scan.*` 归档。
- `batch.plan` 只记计数与批次参数，不记原文、译文与 key；`dedupe.*` 只记 `requestId`、组内 item 数与订阅数，不记文本。
- `batch.done` 的去重计数只在页面提交路径输出；数据面批次只带 `done` / `failed` / `cancelled` 与缓存计数。
- `queue.done` 是一个批次 job 的完成日志（`mode` / `batchItems` / `usage`），`batch.done` 是一次页面提交或数据面批次的终态；两者不合并、不改名。
- 缓存日志只含事件名、`requestId`/`itemId`、计数与字节数；不记录原文、译文、上下文、来源域名、缓存 key 哈希与密钥。命中与未命中记为 `debug`，默认 `info` 下不刷屏。

约束：不按字符记录；只在提交/批次开始、结束、错误与滚动增量汇总处记录。

## 9. 边界情况

- **初始化前调用**：logger 静默，不抛错；入口应尽早初始化。
- **重复初始化**：覆盖级别与版本，不重复安装全局异常监听。
- **非法级别**：归一为 `info`；日志本身不因配置错误中断。
- **`off`**：配置生效后不调用任何 `console.*`；页面注入在收到 `ST_LOG_CONFIG` 前按默认 `info`，可能输出少量连接状态日志，`logger.ready` 在配置后输出。全局异常也不输出（Chrome 扩展错误页仍会显示未捕获异常，这是浏览器行为）。
- **控制台不可用/抛错**：捕获并吞掉，不影响业务。
- **循环引用/大对象**：截断或标记，不抛错。
- **错误对象**：只取安全字段与栈；不直接打印原始对象。
- **扩展上下文失效**：`chrome.runtime.getURL` 或 `chrome.runtime.id` 不可用时，页面注入的全局异常过滤退化为不记录，避免误报。
- **控制台被页面清空**：日志不持久化，刷新/清空即丢失；由用户复制留存。
- **来源为空**：`location.origin` 为 `null`/空（如 `about:blank`、部分 `file://`）时省略 `origin`，不输出 `null`。
- **同一页面多个 frame**：当前清单 `all_frames: false`，只有主 frame；未来开启时每个 frame 独立会话。
- **测试**：用 `resetLogging()` 清理状态；控制台方法用 spy 替换。
