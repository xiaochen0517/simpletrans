## 1. 职责与边界

- 计算稳定缓存 key；在扩展自己的 IndexedDB `simpletrans-cache` 中保存「key → 译文」，并维护容量统计。
- 只负责存取与维护；**是否启用缓存、何时读、何时写**由 A2 决定，本模块不读设置。
- 只有后台可读写：页面注入不引用本模块；设置页只通过 `ST_CACHE_STATS` / `ST_CLEAR_CACHE` 请求后台。
- 缓存是优化而不是前置条件：读失败按未命中、写失败只记日志，都不影响翻译结果。
- 不保存原文、密钥、请求头/体或完整页面 URL；原文只以 SHA-256 哈希形式出现在 key 中。
- 不做 TTL、加密、跨设备同步、导入导出；容量上限调节、按域名统计与清理留给 P8。

## 2. 缓存 key

`buildCacheKey(input)` → `Promise<string>`，形态 `cache:v2:<64 位小写十六进制>`。

| 字段 | 参数 | 归一 |
| ---- | ---- | ---- |
| key 版本 | `CACHE_KEY_VERSION`（当前 `2`） | 固定值，进入前缀与规范串 |
| 引擎类型 | `engineType` | 必填，非空字符串 |
| 模型 | `model` | 必填，非空字符串 |
| 源语言 | `sourceLang` | 缺省 `auto` |
| 目标语言 | `targetLang` | 必填，非空字符串 |
| 提示词版本 | `promptVersion` | 必填；取 A3 `PROMPT_VERSION`（当前 `2`） |
| 批量编码版本 | `batchEncodingVersion` | 必填；取 A3 `BATCH_ENCODING_VERSION`（当前 `1`，P6.4 使用） |
| 思考强度 | `reasoningEffort` | 必填；E3 归一后的 `off` / `low` / `medium` / `high` / `max`，`off` 也进入 key |
| 提示词哈希 | `promptHash` | 必填；A2 用实例模板归一后算出的 SHA-256（64 位十六进制） |
| 每段上下文 | `context` | 缺省空串（当前批次不发送） |
| 原文 | `text` | 必填，非空字符串；不再归一（D1 已归一） |

- 字段按上表顺序组成数组 → `JSON.stringify` → SHA-256 → 十六进制；不用字符串拼接，避免分隔符歧义。
- 必填字段缺失或为空时抛 `TypeError`，调用方按「本批不参与缓存」处理。
- 提示词哈希计算失败同样按「本批不参与缓存」降级；翻译继续。
- 运行环境没有 `crypto.subtle` 时同样抛错，按同一路径降级。
- `promptHash` 由 A2 在每个批次计算一次，不在每段重复计算。
- **域名、引擎实例 id、接口地址、温度、`traceId` 不进入 key**；同类型同模型的实例共享结果。
- **调度参数 `batchSize`、`batchMaxChars`、`maxConcurrency` 不进入 key**：它们只影响切批与并发，不改变单段翻译语义。
- 前缀与版本：key 结构或字段语义变化 → `CACHE_KEY_VERSION + 1`；提示词或输出格式变化 → `PROMPT_VERSION + 1`；批量编码规则变化 → `BATCH_ENCODING_VERSION + 1`；任一变化都让旧条目不再命中。

## 3. IndexedDB 结构

数据库 `simpletrans-cache`，版本 `2`。

```text
entries（keyPath = "key"）
  key         "cache:v2:<sha256>"
  text        译文
  bytes       UTF-8 字节数 + CACHE_ENTRY_OVERHEAD_BYTES
  createdAt   首次写入时间

meta（keyPath = "key"）
  key         同 entries
  bytes       同 entries
  createdAt   同 entries
  lastUsedAt  最近访问时间（命中后按节流回写）
  domain      来源 hostname（小写、无协议/端口/路径；空串表示未知）
  索引 by_lastUsedAt → lastUsedAt（淘汰游标）
  索引 by_domain → domain（P8 按域名统计/清理）

stats（keyPath = "id"，单条记录）
  id            "stats"
  entries       条目数
  bytes         总字节数
  schemaVersion 1
```

- `entries` 只放译文与容量信息，`meta` 只放小体积元数据；命中只更新 `meta.lastUsedAt`，**绝不重写 `entries.text`**。
- 升级（`onupgradeneeded`）时删除并重建三个存储区，不迁移旧缓存；版本 1 的 `cache:v1:` 条目一次性清空，缓存可丢弃。
- 连接懒打开；`versionchange` 与 `close` 时丢弃连接，下次操作重开；打开失败时本次缓存禁用，下次重试。
- 读取只用主键 `get`，淘汰只用 `by_lastUsedAt` 索引游标，统计只读 `stats` 一行；**禁止 `getAll()` / `getAllKeys()` 全表扫描**。
- 事务短小：回调内只等待 IDB 请求，不 `await` 非 IDB Promise，事务 `complete` 后才算成功。

## 4. 接口

```js
createCacheStore({ indexedDB, now, limits })
```

| 方法 | 说明 |
| ---- | ---- |
| `get(key)` | 读一条；结构有效且译文非空才算命中，返回 `{ text, bytes, createdAt }`，否则 `null`；命中后异步回写访问时间。异常返回 `null`。 |
| `getMany(keys)` | 在一个只读事务里并发读多键，返回 `Map<key, entry>`；空数组返回空 `Map`。P6 批量任务复用。 |
| `set(key, text, { generation, domain })` | 写一条；空 key 或空译文本直接返回 `{ written: false, bytes: 0 }`；`generation` 与当前值不一致时跳过。返回 `{ written, bytes }`（失败时 `bytes` 为 0），**不抛出**。 |
| `clear()` | 清空 `entries` / `meta` 并重置统计，返回 `{ cleared, freedBytes }`；统计不可信时按 0 计；失败抛出，由 A1 归一为 `OTHER`。 |
| `stats()` | 返回 `{ entries, bytes, maxBytes, maxEntries }`；只读 `stats` 一行，事务为 `readwrite`（统计损坏时需要同一事务内重建）。 |
| `generation()` | 当前清空代；SW 重建后从 0 开始。 |
| `close()` | 关闭连接（测试与卸载用）。 |

`getCacheStore()` 返回后台单例，A1 与 A2 共用。

`limits` 只用于测试注入：`maxBytes`、`maxEntries`、`evictTargetRatio`、`evictBatch`、`touchIntervalMs`、`touchSetLimit`。

## 5. 容量与淘汰

| 常量 | 值 | 说明 |
| ---- | -- | ---- |
| `CACHE_MAX_BYTES` | `1_073_741_824`（1 GiB） | 应用层保守上限 |
| `CACHE_MAX_ENTRIES` | `1_000_000` | 条目数上限 |
| `CACHE_EVICT_TARGET_RATIO` | `0.9` | 一次淘汰到上限的 90% 以下 |
| `CACHE_EVICT_BATCH` | `500` | 单个事务最多淘汰条数 |
| `CACHE_TOUCH_INTERVAL_MS` | `3_600_000` | 命中回写访问时间的最小间隔 |
| `CACHE_TOUCH_SET_LIMIT` | `2048` | 命中回写节流集合上限 |
| `CACHE_ENTRY_OVERHEAD_BYTES` | `256` | 每条 key/索引/记录开销估算 |

- 字节口径：`new TextEncoder().encode(text).byteLength + CACHE_ENTRY_OVERHEAD_BYTES`，是近似值，用于容量控制与占用展示。
- 每次写入提交后检查统计：字节或条数超过上限就按 `by_lastUsedAt` 从最旧开始删除，每批最多 500 条并更新统计，直到两项都回到上限的 90% 以下；单次触发最多执行 200 批，剩余交给下次写入继续。
- 批的大小是上限而不是差额：一批 500 条可能删到少于目标，条目总数不多时一次可能删完（例如 6 条超限时整批删除）。
- 淘汰与写入、清空共用同一条 Promise 写入队列，避免并发改 `stats`；淘汰不阻塞 `get`。
- 清空时立即递增 generation；淘汰过程中 generation 变化则停止。
- 统计仍超限但条目为 0 时重置统计，避免死循环。
- 清单申请 `unlimitedStorage` 解除浏览器配额与驱逐，但 1 GiB 仍是应用层保守上限。

## 6. 写入、命中与清空

**写入**

1. 校验 key 与译文非空；`generation` 与当前值不一致（例如期间清空过）直接跳过。
2. 进入写入队列，入队后再次校验 `generation`。
3. 一个 `readwrite` 事务写 `entries`、`meta` 与 `stats`：先确保统计可信，再读旧 `meta` 计算字节差（覆盖时保留原 `createdAt` 与首次 `domain`，原 `domain` 为空时用本次值补齐）。
4. 事务 `complete` 后检查容量并按需淘汰；`set` 的 Promise 在写入提交与本次触发的淘汰都结束后 resolve（网关不等待它，不阻塞定稿帧）。
5. 任何异常：先淘汰到上限的 70%，重试一次；仍失败记 `cache.quota` / `cache.error` 并返回 `{ written: false }`。

**命中**

- 只按 key 读取，不读 `meta`、不比较域名；同一原文在不同域名命中时共用同一条缓存。
- 命中后异步回写 `meta.lastUsedAt`：同一 SW 生命周期内同一 key 最多一次，且距上次回写不足 1 小时则跳过；节流集合超过上限后清空，允许少量重复回写。首次命中即占用「本生命周期一次」的机会——若当时因未到间隔而跳过，本生命周期内不再补写。

**统计恢复**

- `stats` 缺失、`schemaVersion` 不符或结构非法：视为缓存不可信，在一个事务内清空 `entries` / `meta` 并重建零值统计，记 `cache.stats.reset`。
- 不做全库扫描；用户只会失去一次缓存命中。

**清空**

- 一个事务内 `entries.clear()`、`meta.clear()`、重置 `stats`，返回清空条数与释放字节。
- 只作用于 `simpletrans-cache`，不删除 `storage.local` 的密钥、`storage.sync` 的设置或 `storage.session` 的任务状态。
- 清空不要求缓存处于启用状态。

## 7. 域名元数据

- `meta.domain` 保存来源 hostname（由 A2 用 `normalizeDomain()` 归一，缺失/非法为空串）；store 只做首尾空白裁剪，不做大小写转换，归一规则只由 A2 / `protocol.js` 负责。只作为元数据，供 P8 按域名统计与清理。
- 域名不进入 key、不参与命中、不进入提示词、不进入日志。
- 新建条目使用本次 `domain`；覆盖已有条目保留首次写入的 `domain`，原值为空时用本次值补齐。
- `by_domain` 索引供 P8 的 `removeByDomain` 之类操作使用，P5 不提供按域名清理界面。
- 空串 `domain` 不参与按域名统计与清理。

## 8. 日志

| 事件 | 级别 | 内容 |
| ---- | ---- | ---- |
| `cache.evict` | `info` | 淘汰条数、释放字节、剩余条数与字节 |
| `cache.clear` | `info` | 清空条数、释放字节 |
| `cache.quota` | `warn` | 写入失败与重试结果、本次字节数 |
| `cache.error` | `warn` | 读/写/打开失败摘要；只带错误名与截断后的消息 |
| `cache.stats.reset` | `warn` | 统计缺失或结构不符，已清空重建 |

- 不记录原文、译文、上下文、域名、key 哈希、密钥与地址。
- 日志失败不影响缓存与翻译。

## 9. 边界情况

- `indexedDB` 不可用或打开失败：读按未命中、写返回 `{ written: false }`，下次操作重试。
- 记录结构非法（缺 `text`、`bytes` 非正）：按未命中处理。
- 覆盖同一 key：翻译结果更新但条目不增加，字节按差值更新，保留首次 `createdAt` 与 `domain`。
- 并发写入串行执行，`stats` 不会互相覆盖。
- SW 被回收：未提交事务回滚，已提交结果保留；`generation` 与写入队列只存在于当前 SW，重建后以 IndexedDB 中的 `stats` 为准。
- 磁盘写满或文件系统错误：先淘汰到 70% 再重试一次，仍失败只放弃本次写入。
- 缓存关闭由 A2 判断，本模块不读设置；关闭期间缓存条目保持不变。
