源码：`src/content/bridge.js`，入口 `src/content/index.js`。

## 1. 职责与边界

- 在页面注入侧维持与后台的 `st-gateway` 长连接，供 P4/P6 发批、收帧、取消；每个 frame 各有一个桥实例，后台按 `tabId + frameId` 识别。
- 只做通道：不操作 DOM、不读写 `storage`、不引用 `shared/config`、`shared/translate`、`shared/cache`。
- 任务状态、段落与进度归页面任务（P6），桥只记录「已发出但未收到 `ST_BATCH_DONE` 的 requestId」。

## 2. 接口

```js
const bridge = createBridge({ onFrame, onStateChange, onDisconnect });
bridge.connect();
bridge.getState();
bridge.send(frame);                 // 未连接时抛 BridgeError
bridge.postBatch({ requestId, traceId, domain, targetLang, context, items });
bridge.cancelBatch(requestId);
bridge.cancelItem(requestId, itemId);
bridge.close();
```

- `BridgeError` 与协议错误对象同形：`{ code, message, reason }`。
- `onFrame` 收到除 `ST_PONG` 以外的所有后台帧（含 `ST_LOG_CONFIG`）；`ST_PONG` 由桥内部消费。
- 日志级别帧由 `content/index.js` 处理：收到 `ST_LOG_CONFIG` 后调用 E4 的 `setLogLevel`；桥不解释级别。
- `onDisconnect(pendingRequestIds)` 在断开时调用；没有在途请求时传空数组。

## 3. 状态机

```text
idle → connecting → connected
                  ↘ reconnecting → connected
connected → reconnecting（断开 / 心跳超时）
connected/reconnecting → closed（close / 扩展上下文失效）
```

- `connect()` 与 `close()` 幂等；`connected`/`connecting` 时重复 `connect()` 不做事。
- 连接后立即发一帧 `ST_PING` 作为握手；收到 `ST_PONG` 才算 `connected`。
- `connected` 后每 20 秒发 `ST_PING`；发出后 10 秒未收到 `ST_PONG` 视为半死连接，主动断开并重连。
- 重连退避 1/2/4 秒，之后固定 4 秒；连接成功后重置。`reconnecting` 期间 `send` 抛 `NETWORK`/`NOT_CONNECTED`。
- `pagehide` 时发 `ST_CLOSE` 并断开；`pageshow` 且 `persisted` 时重连。

## 4. 断线与扩展上下文失效

- 后台断开：清空计时器，通知 `onDisconnect`，进入 `reconnecting` 并按退避重连。
- 断线时在途批次不自动重发（P9 负责）；P4/P6 收到 `onDisconnect` 后暂停新批。
- 扩展重载/更新后旧内容脚本的扩展上下文失效：`chrome.runtime.id` 为空，或抛 `Extension context invalidated` / `message port closed`。
- 失效时进入 `closed`，只提示一次「扩展已重新加载，请刷新页面」，不再无限重试。
- 桥不把「心跳丢失」当作任务失败；任务失败由页面任务根据帧与超时决定。

## 5. 日志

使用 E4（`src/shared/log/`），不直接调用 `console.*`；日志只输出控制台，不写存储。

| 事件 | 级别 | 内容 |
| ---- | ---- | ---- |
| `bridge.state` | info | 连接状态变化 |
| `bridge.heartbeat` | debug | 心跳计数与 RTT |
| `bridge.reconnect` | debug | 退避等待毫秒数 |
| `bridge.invalidated` | info | 扩展上下文失效，提示刷新页面 |
| `log.config` | debug | 收到 `ST_LOG_CONFIG` 后的级别（由入口记录） |

- 级别由 E4 与设置决定；默认 `info`，`debug` 需在设置页或 DevTools 打开 Verbose。
- 页面注入在连接建立后收到一次级别，刷新/重连后生效。
- 日志不得包含密钥、页面原文、完整 URL；只记录状态、计数与耗时。

## 6. 边界情况

- 未连接时 `postBatch`/`send` 抛 `BridgeError(NETWORK, NOT_CONNECTED)`，不发帧。
- `postBatch` 成功后把 `requestId` 记入在途；收到 `ST_BATCH_DONE` 或断线时移除。
- 收到未知帧仍交给 `onFrame`（便于后续阶段扩展），桥不做业务判断。
- 页面关闭时 `ST_CLOSE` 是尽力发送；后台以端口断开为准清理。
- 桥不缓存帧、不重发批次、不合并增量（合并与节流由 P4 渲染负责）。
