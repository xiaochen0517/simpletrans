# A2 请求网关

| 日期 | 结论 |
| ---- | ---- |
| 20261115 | 初稿（P2：批次校验、并发、取消、断线、批超时） |

源码：`src/background/gateway.js`。

## 1. 职责与边界

- 接收 `st-gateway` 端口上的数据面消息，返回增量、定稿与终态。
- 负责载荷校验、全局并发、每连接在途批次、取消、断线与批超时。
- **不保存任务状态**：批次表、控制器、计时器只在当前 Service Worker 事件循环的内存里；不写 `storage`、不写缓存、不做恢复。
- 不重试、不切备用、不查缓存；这些分别在 P8、P8、P4。

## 2. 连接与心跳

- 只接受端口名 `st-gateway`、发送方 `sender.id === chrome.runtime.id` 的端口；其它端口直接断开。
- 每个端口维护 `{ port, batches: Map<requestId, batch>, disconnected }`。
- `ST_PING` 立即回 `ST_PONG { sentAt, receivedAt }`，不进入批次表、不占并发名额、不写存储。
- 端口 `onDisconnect` 或 `ST_CLOSE`：中止该端口全部在途上游请求、清空批次表与计时器；断线后不再发帧。

## 3. 批次执行

1. 校验（顺序见 [E1-消息协议](./E1-消息协议.md) 第 6 节）；任一失败只回一帧 `ST_BATCH_DONE { ok: false, error }`，不创建批次。
2. 读取设置、实例列表首个实例、密钥；没有实例、缺密钥或实例无效时整批 `CONFIG`。网关**不创建实例、不写存储**。
3. 创建批次并设置 180 秒批超时；批次内各段**逐段顺序**执行（P2 不做批量编码）。
4. 每段：取全局名额 → `ST_ITEM_START` → `translate(item, signal)` → 转发 `ST_ITEM_DELTA` → `ST_ITEM_DONE` 或 `ST_ITEM_ERROR`。
5. 全部段结算后回 `ST_BATCH_DONE { requestId, ok, done, failed, cancelled }`。

### 并发

- 全局上游并发上限 `min(settings.concurrency, 4)`，默认 3；信号量 FIFO，按「段」获取。
- 每端口在途批次 ≤ 4；超出立即 `TOO_MANY_INFLIGHT`，不在后台排队。
- 设置页测试翻译通过 `withUpstreamSlot(fn, limit)` 复用同一个信号量，不绕过上限。
- 悬停的交互预留（1 个名额）在 P3/P5 引入，P2 不分优先级。

### 取消

| 操作 | 排队中 | 执行中 | 已完成 |
| ---- | ------ | ------ | ------ |
| `ST_CANCEL_ITEM` | 标记取消，不发帧 | abort → `ST_ITEM_ERROR(CANCELLED)` | 忽略 |
| `ST_CANCEL_BATCH` | 全部标记取消，不发帧 | abort → 当前段 `ITEM_ERROR(CANCELLED)`，其余不结算 | 保留 |
| 端口断开 | 全部丢弃，不发帧 | abort，不发帧 | 保留（页面内存随页面销毁） |

取消是幂等的；取消后仍发一次 `ST_BATCH_DONE` 作为终态，`cancelled` 为未结算段数。

### 批超时

- 计时器在批次创建时启动，`AI_TIMEOUT_MS.batchTotal`（180 秒）。
- 到期：中止当前段，所有未结算段（含未开始的段）以 `ST_ITEM_ERROR(NETWORK, BATCH_TIMEOUT)` 结算，然后回 `ST_BATCH_DONE`。
- 未开始的段可能没有对应的 `ST_ITEM_START`，客户端按 `requestId`/`itemId` 结算。

## 4. 错误映射

| 场景 | 错误码 |
| ---- | ------ |
| 载荷/字段/语言/在途超限 | `OTHER` |
| 缺实例、缺密钥、实例无效 | `CONFIG` |
| 鉴权、额度（来自 A3） | `AUTH` |
| 限流（来自 A3） | `RATE_LIMIT` |
| 网络、超时、流中断、批超时 | `NETWORK` |
| 用户取消 | `CANCELLED` |

P2 只回传错误，不执行重试、拆批与备用切换。

## 5. 边界情况

- 报文不是对象、类型未知、`payload` 缺失：回 `ST_BATCH_DONE`（`INVALID_MESSAGE`）。
- 同端口在途批次重名：`DUPLICATE_REQUEST`；批次结束后同名可复用。
- 一个批次失败不影响其它批次；同一端口最多 4 个在途批次。
- 端口发送失败（已断开）按断线处理，清理该端口并中止在途请求。
- 网关不读取 `storage.session`，不写 `storage.local` / `storage.sync`。
