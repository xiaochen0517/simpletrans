## 1. 职责与边界

- 接收 `st-gateway` 端口上的数据面消息与页面注入的统一段落提交（`ST_PAGE_SUBMIT`），返回增量、定稿与终态。
- 页面提交路径：按 `tabId` 找到页面连接，按 `requestId` 建立提交；读取设置并按「当前实例 → 其它实例」找第一个可用实例（类型受支持、启用、凭据完整、endpoint 已授权），取该实例凭据，一次预取缓存并立即回显命中项，未命中项按唯一 key 分组、按实例参数切批，交给 A3 队列翻译，段结果逐段回帧。
- 数据面路径：保留 `ST_TRANSLATE_BATCH`（协议兼容与测试），负责载荷校验、全局并发、每连接在途批次、取消、断线与批超时。
- 负责按段的缓存查询与命中结算，并在每个段结果到达后写缓存；缓存结构、容量与淘汰由 A4 负责；按实例类型计算缓存 profile（OpenAI 用 endpoint 指纹与生成参数哈希，百度用固定 profile）。
- 负责 `inFlightByKey` 在途复用：同 key 的 group 只执行一次，跨提交、跨连接订阅同一结果。
- **不保存任务状态**：批次表、提交表、在途共享表、控制器与计时器只在当前 Service Worker 事件循环的内存里；不写 `storage`、不做恢复。
- 负责百度实例的 QPS 门控、批量对齐失败时的二分拆批与标签页关闭兜底清理；重试由 A3 队列在同一实例内执行；队列调度、JSONL 编码与解析由 A3 负责；`ST_TEST_ENGINE` 不进入提交、批次计划与在途复用，也不读写缓存，但受 QPS 与全局并发约束。

## 2. 连接与心跳

- 只接受端口名 `st-gateway`、发送方 `sender.id === chrome.runtime.id` 的端口；其它端口直接断开。
- 每个端口维护 `{ port, tabId, batches, submissions, disconnected, logConfigSent }`。
- `handleConnect` 按 `sender.tab.id` 把连接登记到 `tabConnections`；同一标签页建立新连接时记 `gateway.replace` 并清理旧连接，断开时同步删除。`findConnectionByTab(tabId)` 供一次性提交按 `tabId` 找连接。
- `ST_PING` 立即回 `ST_PONG { sentAt, receivedAt }`，不进入批次表、不占并发名额、不写存储。
- 每个连接首个 `ST_PING` 后，若 `logConfigSent` 为假，先置为真，再异步读取设置并补发一帧 `ST_LOG_CONFIG { level }`；每连接只发一次，重连后的新连接重新下发。读取失败时用当前缓存级别（默认 `info`），不因下发失败断开连接；不做级别变更推送。
- 端口 `onDisconnect` 或 `ST_CLOSE`：中止该端口全部在途上游请求、清理批次表、提交表与在途订阅；断线后不发帧。
- `cleanupTab(tabId)` 由 `gateway.js` 导出，并注册在 `src/background/index.js` 的 `chrome.tabs.onRemoved`：按 `tabId` 找到连接后清理连接、结束提交、摘除订阅、abort 无订阅者的共享执行；与端口断线清理幂等。日志 `tab.cleanup`（info：`tabId` / `pendingSubmissions` / `pendingBatches` / `sharedReleased`）。

## 3. 页面提交与批次处理

### 3.1 提交入口

```text
page (D5) --ST_PAGE_SUBMIT--> A1.receivePageSubmit
  形状校验（scope / requestId / 段落 / hostId / 禁止字段）
  → sender.tab.id → findConnectionByTab
      找不到：返回 { ok: false, error: { code: NETWORK, reason: NOT_CONNECTED } }「页面通道未连接，请刷新后重试」
  → acceptPageSubmit({ requestId, traceId, scope, targetLang, domain, viewport, paragraphs, tabId })
  → 初始化、缓存预取与命中回显后返回 { ok: true, data: { accepted: true, requestId, scope, paragraphs, chars } }；未命中翻译异步执行
A2.acceptPageSubmit:
  → 按 tabId 找连接、检查 requestId 重复
  → 分流超长 item：字符 > MAX_SEGMENT_CHARS，或百度实例 UTF-8 字节 > 4800；不进入分组、切批与缓存
  → 读取设置 / 当前实例与凭据 / 目标语言
  → 按实例类型计算缓存 profile → 为其余段落计算 key → 一次 getMany
  → 创建提交；超长段逐段 ITEM_ERROR(TEXT_TOO_LONG)
  → 命中：逐段 START → DONE
  → 未命中：唯一 key 分组 → 已在途 group 只订阅，其余切批（百度另按字节）→ 每个 batch 入 A3 队列
  → 段结果到达即写缓存并 fan-out；全部 item 结算后 BATCH_DONE + batch.done
```

```js
// router.js
receivePageSubmit(payload, sender, traceId)
  → { ok: true, data: { accepted, requestId, scope, paragraphs, chars } }
  | { ok: false, error }

// gateway.js
acceptPageSubmit({ requestId, traceId, scope, targetLang, domain, viewport, paragraphs, tabId })
  → { accepted: true }
  | { accepted: false, error }
```

- `acceptPageSubmit` 的参数：`requestId`（页面生成的 `s-…`）、`traceId`、`scope`（`page` / `single`，只影响日志与校验，不改变分组与切批）、`targetLang`（缺省读设置）、`domain`（页面 hostname）、`viewport`（只随提交透传，当前不参与缓存、分组与切批）、`paragraphs`（`{ hostId?, text }`，按页面顺序）、`tabId`（结果帧路由键）。
- A1 只做形状校验、计数与回执，不查缓存、不调用引擎；A2 初始化失败时 A1 仍返回 `accepted: true`，失败通过逐段 `ST_ITEM_ERROR` + `ST_BATCH_DONE(ok:false)` 表达。
- 同一连接内 `requestId` 重复时拒绝（`DUPLICATE_REQUEST`），避免结果串台；提交结束、连接清理后同一 `requestId` 可复用。无 `requestId` 的匿名提交使用内部键 `anon-N` 登记、不参与重复判定；页面始终生成 `s-…`，匿名路径只用于兼容与测试。
- A1 等到 A2 完成初始化、一次缓存预取与命中回显后回执；未命中项的分组、切批、入队与翻译异步执行，不等待翻译完成。
- 初始化失败（读取设置失败、扩展停用、目标语言不支持、没有可用实例、实例停用/结构无效/类型不支持、凭据不完整、endpoint 未授权、读取实例失败）逐段发 `ST_ITEM_ERROR(code, message)`，再发 `ST_BATCH_DONE { ok: false, failed: 段落数 }`；不能只发 `BATCH_DONE`，否则页面停在「已提交」。提示按原因细化：「没有可用的翻译实例」「当前实例已停用」「缺少密钥」「APPID 或密钥未配置完整」「未授权访问该接口域名」。key 计算与缓存读取失败只降级处理，不算初始化失败。
- 缓存命中帧可能早于 `ST_PAGE_SUBMIT` 的回执到达；D5 发送前先登记临时提交记录（状态 `submitting`），命中帧可直接按 `requestId + itemId` 路由；提交失败时 D5 把未结算段落标错并清理临时记录。
- 页面提交按 `requestId` 去重，不计入数据面每端口 4 批的在途额度。
- 提交创建时启动超时（OpenAI 实例 180 秒 `AI_TIMEOUT_MS.batchTotal`，百度实例 30 秒 `BAIDU_TIMEOUT_MS.batch`），早于 A1 回执返回；QPS 窗口、队列与重试等待均计入该超时。
- 数据面 `ST_TRANSLATE_BATCH` 路径保留给协议兼容与测试，页面不走该路径；结果主路径是 `ST_PAGE_SUBMIT`。
- `ST_CANCEL_BATCH` 由页面在清除前发送（`cancelRequest` → `bridge.cancelBatch`）；`ST_CANCEL_ITEM` 保留给协议与内部使用，页面暂不发送。

### 3.2 缓存预取与命中回显

- 缓存开关取 `settings.cacheEnabled`（缺省为开）。缓存关闭时仍计算 key 用于同 key 分组与在途复用，但不读、不写 IDB，命中数为 0。
- key 由 A4 `buildCacheKey` 计算；profile 按实例类型取：OpenAI 用 A3 `buildLLMProfile` 的 `endpointFingerprint` / `generationHash` + 实例提示词哈希；百度固定 `baidu` / `general` / `none` / `baidu:v1` / 提示词版本 0。`batchEncodingVersion` 来自 A3 常量。
- profile 或任一段 key 计算失败：本次提交不参与缓存，分组键回退为 `fallback:<text>`，记 `cache.error`，翻译继续。
- 读取：全部唯一 key 在一个只读事务中 `getMany`；唯一 key 为空时不查缓存；读取异常按全部未命中处理，写缓存仍尝试，记 `cache.error`。
- 命中 group：为组内每个 item 发 `ST_ITEM_START` → `ST_ITEM_DONE(text)`；`usage` 为 `null`；`cacheHits` 按原始 item 累计；不占队列名额；不重复写缓存。
- 命中项按页面顺序回帧，允许与未命中项的 `START` / `DONE` 交错。
- 命中仍要求实例可用（凭据完整、endpoint 已授权）：缓存读取在设置、实例与凭据检查之后。
- 提交创建时捕获 A4 generation；写入时 generation 不一致则跳过（沿用 P5）。
- 命中不更新条目的 `text`；`meta.lastUsedAt` 由 A4 `getMany` 的既有节流逻辑处理；key 版本为 `cache:v3:`。

### 3.3 唯一 key 分组与切批

```text
acceptPageSubmit:
  按 tabId 找连接 / 检查 requestId 重复
  → 分流超长段（字符 > MAX_SEGMENT_CHARS；百度实例 UTF-8 字节 > 4800；直接失败、不进入分组）
  → 读取设置 / 当前实例与凭据 / 目标语言
  → 为其余段落计算 key（缓存关闭也计算，用于去重）
  → 按 groupKey 分组（同 key 的段落合并为一个 group）
  → cacheEnabled ? getMany(uniqueKeys) : 全部未命中
  → 超长段逐段 ITEM_ERROR(TEXT_TOO_LONG)
  → 命中 group 逐段回显
  → missGroups 分成 inFlightGroups（已有共享执行）与 newGroups
  → splitBatches(newGroups, { batchSize, batchMaxChars, batchMaxBytes }) → 每个 batch 分配 id（b0、b1…）
  → 创建 shared、发 START、入 A3 队列
  → 段结果到达即写缓存并 fan-out；全部 item 结算后 BATCH_DONE + batch.done
```

- 分组键是 `cacheKey`；key 失败时是 `fallback:<text>`。`group.text` 取第一个 item 的文本；同 key 的原文、模型、语言、生成参数与提示词一致。
- 分组不改变页面 `itemId`：`hostId` 兼作结果帧 `itemId`，缺失时用 `p-<index>` 占位；每个原始段落仍各自结算与计数。
- 单段超过 `MAX_SEGMENT_CHARS`（4000 字符）或百度实例超过 4800 UTF-8 字节的段落不进入分组、切批与缓存，提交创建后逐段以 `TEXT_TOO_LONG` 失败；其余段落继续，提交按部分成功处理。未超过上限但超过 `batchMaxChars` / `batchMaxBytes` 的 group 单独成批并标记 `oversize`。
- `cacheEnabled` 只控制缓存读写，不控制分组与切批。
- 同提交内同 key 的段落合并到一个 group：`dedupeHits += group.items.length - 1`，记 `dedupe.merge`；同一 group 只执行一次上游，`done` / `failed` / `cancelled` 仍按原始 item 计数。
- 已在途的 group 不进入新批次：先按 `inFlightByKey` 筛出 `inFlightGroups`，只对 `newGroups` 切批；批次等待期间新提交的同 key 段落也只订阅，不重复入队。
- 切批参数取实例值：OpenAI `batchSize` 默认 8、不设业务上限；百度 `batchSize` 1–20、默认 8。`batchMaxChars` OpenAI 默认 1000、不设固定上限；百度 1–2000、默认 1000。`batchMaxBytes` 只有百度使用（4800 字节），OpenAI 不限制。缺失或非法时归一为默认值。
- 三个限制同时生效、先到先切：`batchSize` 限制 group 数，`batchMaxChars` 限制组内原文 `text.length` 之和，`batchMaxBytes` 限制组内 UTF-8 字节之和（含段间换行分隔符）；以 group 为单位切分，绝不拆段；空批次不产生。

```js
function splitBatches(groups, { batchSize, batchMaxChars, batchMaxBytes }) {
  const maxBytes = Number.isFinite(batchMaxBytes) ? batchMaxBytes : Infinity;
  const batches = [];
  let current = [];
  let chars = 0;
  let bytes = 0;

  const flush = () => {
    if (current.length === 0) return;
    batches.push({
      groups: current,
      chars,
      bytes,
      oversize: current.some(
        (group) => group.text.length > batchMaxChars || utf8Bytes(group.text) > maxBytes
      ),
      emitted: false,
      state: 'pending',
    });
    current = [];
    chars = 0;
    bytes = 0;
  };

  for (const group of groups) {
    const length = group.text.length;
    const groupBytes = utf8Bytes(group.text);
    const separator = current.length > 0 ? 1 : 0;
    if (
      current.length > 0 &&
      (current.length >= batchSize ||
        chars + length > batchMaxChars ||
        bytes + separator + groupBytes > maxBytes)
    ) {
      flush();
    }
    current.push(group);
    chars += length;
    bytes += (current.length > 1 ? 1 : 0) + groupBytes;
    if (current.length >= batchSize) flush();
  }
  flush();
  return batches;
}
```

- `oversize` 只用于 `batch.plan` 的 `oversizeBatches` 计数，不改变执行方式；超长段单独成批后按单段请求执行。
- 批次顺序与页面提交顺序一致；不做视口优先重排。
- 例：20 个不同文本的段落、每段 100 字符、`batchSize=8`、`batchMaxChars=1000` → 3 批（8 / 8 / 4 组，800 / 800 / 400 字符）；`batchMaxChars=300` → 每批 3 组、300 字符（末批 2 组、200 字符）；其中一段 3000 字符 → 单独一批，`oversize=true`。百度实例每段 100 个汉字（300 字节）、`batchMaxBytes=1000` → 每批 3 组（902 字节）。
- 协议硬上限 `MAX_BATCH_ITEMS=12`、`MAX_BATCH_CHARS=12000` 只用于数据面 `ST_TRANSLATE_BATCH` 校验；页面提交的内部批次由实例参数控制，可能超过 12000 字符，`batchChars` 记入 `batch.plan` 便于发现过大批次。

```js
group = {
  key, cacheKey, text,
  items: [],           // 同 key 的原始 item
  cacheEntry: null,
  shared: null,        // 共享执行；批次中由 jobHandle 关联 A3 队列
  state: 'pending',    // pending / cache-hit / owner / subscribed
};

batch = {
  id,                  // b0、b1…，只用于日志；二分拆批的子批次追加 a / b
  groups, chars, oversize,
  emitted,             // 是否已产生输出；true 后队列不再自动重试
  state: 'pending',    // pending / running / done / failed / split
  depth, parentId,     // 二分拆批后的层级与父批次 id
};
```

- `batch` 不进入页面帧，只用于日志与队列入参；一个 batch 对应 A3 队列的一个 job。

### 3.4 在途复用与队列 job

```js
shared = {
  key, group, cacheKey, text,
  cacheEnabled, cacheGeneration, domain,
  subscribers: Set<{ submission, item }>,
  owner: { submission, item } | null,   // 只负责增量与 usage 归属
  state: 'running' | 'done' | 'failed' | 'cancelled',
  jobHandle: { jobId, cancel, dropGroup } | null,
  startedAt,
  ownerSubmission,
};

job = {
  requestId, batchId,
  groups,                     // batch.groups
  targetLang, sourceLang, instance,  // instance 含该实例凭据（apiKey 或 appId/secretKey）
  concurrency,                // 实例 maxConcurrency
  withSlot: (fn, limit, signal) => withUpstreamSlot(fn, limit, instance, signal),
  canRetry: () => !batch.emitted && !batch.cancelled && !submission.timedOut,
  onDelta, onItem, onBatchDone, onBatchError,
};
```

- `batch.emitted` 在单段批发出过 `ST_ITEM_DELTA`、或多段批解析出任意段后置为 `true`；此后 `canRetry()` 为假，A3 队列不再重试该批次。
- `canRetry()` 同时要求批次未取消、提交未超时，避免重试已取消或已按 `BATCH_TIMEOUT` 结算的请求。

```text
for group of inFlightGroups:
  订阅 inFlightByKey.get(group.key)（dedupeJoined）
for group of newGroups:
  shared = createShared(group); 订阅 owner；记 dedupe.owner
translationQueue.setConcurrency(limit)
for batch of batches:
  handle = translationQueue.enqueueBatch(createBatchJob(batch))
  batch.groups[*].shared.jobHandle = handle
```

- `inFlightByKey` 以 group 键索引，同一个 key 在当前 Service Worker 内存里只保留一个 `shared`；跨提交、跨连接复用。
- 订阅：为 group 内每个 item 发 `ST_ITEM_START`，把 `{ submission, item }` 加入 `shared.subscribers`；创建者组的第一个订阅者成为 `owner`。跨提交订阅按 item 累计 `dedupeJoined`，创建 shared 的提交累计 `dedupeShared`。
- 每批只占 1 个队列名额；批次内部再经 `withUpstreamSlot` 取全局上游名额。`maxConcurrency` 同时限制队列在途批次数与上游请求数。
- 单段批（1 个 group）由队列调用 `translate`：`ST_ITEM_DELTA` 只发给 owner 的 item，其它订阅者不发增量、直接等定稿；成功定稿时 owner 带上游 `usage`，其余为 `null`。
- 多段批（2 个及以上 group）由队列调用 `translateBatch`：一次 JSONL 请求，每解析出一段就 `onItem`；不发送 `ST_ITEM_DELTA`，每个订阅者收到的 `ST_ITEM_DONE.usage` 为 `null`。
- 段结果到达：`resolveShared` 从在途表删除，按 group 写一次缓存（先 fan-out，再异步写入），对当前订阅者发 `ST_ITEM_DONE`；同组其它订阅者也收到同一译文。
- 批量结果对不上：已解析段照常结算；未结算 group ≥ 2 时先二分拆批重试，子批次仍失败或只剩 1 段时才以 `BATCH_ALIGN` 失败；已成功段不回滚。
- 批量中某段译文为空：只把该 group 以 `OTHER`「引擎返回空译文」失败，其它 group 继续。
- 失败：从在途表删除，`state = 'failed'`，记 `dedupe.error`（warn）；对全部订阅者发 `ST_ITEM_ERROR(code, message)`；不写缓存。
- 二分拆批：`BATCH_ALIGN` 且未结算 group ≥ 2 时，把未结算 group 按原顺序对半分给两个子批次（新 batchId 为父批次 id 追加 `a` / `b`，`depth` 递增）；子批次沿用同一 group 对象、共享执行与提交上下文，父批次 `state = 'split'`。子批次加入 `submission.batches`，每个 group 的 `jobHandle` 改指子批次后重新入队；单段仍失败才标 `BATCH_ALIGN`。
- `handleJobDone` 对未被解析的 group 同样先尝试二分拆批；拆批后只有全部原始 item 结算完才发一次提交级 `ST_BATCH_DONE`。日志 `batch.split`（info：`requestId` / `batchId` / `parentGroups` / `leftGroups` / `rightGroups` / `depth`）。
- 重试交接：A3 只对 `NETWORK` / `RATE_LIMIT` 等 `retryable` 错误重试；A2 通过 `canRetry()` 告知是否已产生输出、已取消或已超时。重试不重置 `groups`，成功只回调一次 `onBatchDone`，最终失败只回调一次 `onBatchError`。

### 3.5 取消、超时与断线

| 操作 | 排队中 / 未开始 | 共享执行中 | 已结算 |
| ---- | --------------- | ---------- | ------ |
| `ST_CANCEL_ITEM` | 摘除订阅并结算该 item；group 无订阅者时从 job 摘除 | 从 `shared.subscribers` 移除该订阅；group 无订阅者时从 job 摘除并记 `dedupe.abort`；job 无 group 时 abort；页面已移除显示，不补发取消帧 | 忽略 |
| `ST_CANCEL_BATCH` | 取消该提交全部未结算 item，不发帧；逐个 group 从 job 摘除 | 同上；全部 group 无订阅时 abort job | 保留；全部结算后发 `ST_BATCH_DONE` |
| 提交超时（OpenAI 180 秒 / 百度 30 秒） | 未结算 item 以 `NETWORK / BATCH_TIMEOUT` 失败并发 `ST_ITEM_ERROR`；无订阅 group 从 job 摘除 | 同上；有其它订阅的 group 继续 | 保留 |
| 端口断开 | 该连接全部提交标记结束、清理订阅，不发帧；无订阅 group 从 job 摘除 | 同上 | 保留 |
| 同一标签页新连接覆盖旧连接 | 旧连接按断开处理 | 同上 | 保留 |

- 取消、超时与断线只影响本提交/本连接的订阅，不影响其它提交与连接；group 仍有订阅者时继续执行。
- 排队等待百度 QPS 窗口或全局并发名额时可被取消：QPS 等待立即结束并抛 `CANCELLED`，不再发上游请求；全局名额等待由队列取消路径摘除订阅。
- 结算顺序：先摘除订阅并结算 item，再在无订阅者时 `dropGroup`；避免队列的取消回调早于 item 结算。
- 已结算 item 的迟到帧忽略；页面发起的取消已经在页面移除显示，因此不补发 `CANCELLED` 帧。
- 页面在清除前发送 `ST_CANCEL_BATCH`（每个未结束提交一次）；`ST_CANCEL_ITEM` 仍保留给协议与内部使用，页面暂不发送。

### 3.6 计数

| 计数 | 口径 |
| ---- | ---- |
| `done` / `failed` / `cancelled` | 按原始 item 计；同 key 合并后的 group 不改变该口径 |
| `cacheHits` | 命中缓存的原始 item 数（按 item 回帧时累计） |
| `cacheMisses` | 未命中的 group 数（含只在途订阅的 group；仅缓存启用且 key 计算成功时累计） |
| `cacheWrites` | 尝试写缓存的 group 数（创建 shared 的提交累计） |
| `dedupeHits` | 同提交内因同 key 合并而少执行的 item 数（`group.items.length - 1` 之和） |
| `dedupeShared` | 本提交创建 shared 的 group 数 |
| `dedupeJoined` | 本提交订阅其它在途 shared 的 item 数 |
| `uniqueGroups` | 本次提交的唯一 group 数 |
| `batches` | 本次提交新建的批次数，含二分拆批产生的子批次（不含只在途订阅的 group） |

计数随 `batch.done` 输出；超长段的失败计入 `failed`，因此发出 `ST_BATCH_DONE` 时 `done + failed + cancelled` 仍等于提交的原始段落数。

## 4. 数据面批次执行

`ST_TRANSLATE_BATCH` 保留给协议兼容与测试，页面不走该路径；本节的校验、并发与超时语义对该路径生效。

1. 校验（顺序见 [E1-消息协议](./E1-消息协议.md) 第 6 节）；任一失败只回一帧 `ST_BATCH_DONE { ok: false, error }`，不创建批次。
2. 读取设置与当前可用实例（类型受支持、启用、凭据完整、endpoint 已授权）及其凭据；没有实例、凭据不完整或实例无效时整批 `CONFIG`。网关**不创建实例、不写存储**。
3. 缓存启用时先按实例类型计算 profile，再逐段计算 key，并在一个只读事务中读取本批 key；命中结果随批次创建一起记录。
4. 创建批次并设置批超时（OpenAI 180 秒 / 百度 30 秒）；批次内各段**逐段顺序**执行。
5. 每段：命中 → `ST_ITEM_START` → `ST_ITEM_DONE`；未命中 → 取全局名额 → `ST_ITEM_START` → `translate(item, signal)` → 转发 `ST_ITEM_DELTA` → `ST_ITEM_DONE` 或 `ST_ITEM_ERROR`；成功定稿后异步写缓存。
6. 全部段结算后回 `ST_BATCH_DONE { requestId, ok, done, failed, cancelled }`。

### 缓存

- 缓存开关取 `settings.cacheEnabled`（缺省为开）；关闭时**不做 key 计算、不读 IDB、不写 IDB**，行为等同全部未命中。
- key 由 A4 `buildCacheKey` 计算，输入为 key 版本、引擎类型、endpoint 指纹、模型、`settings.sourceLang`、目标语言、提示词版本、提示词哈希、生成参数哈希、`BATCH_ENCODING_VERSION` 与原文；OpenAI profile 来自 A3，百度使用固定 profile。profile、提示词哈希或任一 key 计算失败 → 本批不参与缓存（全部未命中且不写），记 `cache.error`。
- profile 每个批次只算一次，不在每段重复计算；成功计算后以 `cache.key.version`（debug）记录当前 `CACHE_KEY_VERSION`，不记哈希。
- 读取用一个只读事务读本批全部 key；读取异常按全部未命中处理，仍尝试写入，记 `cache.error`。
- 命中段：发 `ST_ITEM_START` 与 `ST_ITEM_DONE`，`usage` 为 `null`，不发 `ST_ITEM_DELTA`，不占上游并发名额，不调用 A3。
- 未命中段：走原流程；`ST_ITEM_DONE` 发出后**异步**调用 A4 `set()`，写入失败只记日志，不改变该段结果。
- 只写「A3 成功且译文非空」的定稿；失败、取消、批超时、空译文一律不写。
- 批次携带 `domain`（页面 hostname），网关用 `normalizeDomain()` 归一；缺失、非字符串、超长或非法字符按空串处理，**不拒绝批次**。域名只写入未命中成功后的 `meta.domain`，不参与 key、不参与命中、不进入提示词与日志。
- 批次开始时捕获 A4 的 generation；用户清空缓存后，旧批次尚未完成的写入被跳过。
- 命中仍要求实例可用（凭据完整、endpoint 已授权）：缓存读取在校验、设置、实例与凭据检查之后，不改变缺凭据/未授权的拒绝语义。

### 并发

- 全局上游并发上限取当前实例 `maxConcurrency`（OpenAI 默认 4、不设固定上限；百度 1–10、默认 1）；信号量 FIFO。
- 页面提交按「批次」获取队列名额与全局名额：一个 batch 一次上游请求，只占 1 个队列名额。
- 数据面按「段」获取名额，每段一次单段 `translate`。
- 并发来源只有实例 `maxConcurrency`；`settings.concurrency` 仅作旧实例迁移回退。
- 每端口数据面在途批次 ≤ 4；超出立即 `TOO_MANY_INFLIGHT`，不在后台排队。页面提交不受该额度限制，只按 `requestId` 去重。
- 设置页测试翻译把当前实例传给 `withUpstreamSlot`，复用同一个信号量并受该实例 QPS 限制；测试翻译不自动重试。
- 百度实例先过 QPS 门控再占全局并发名额：`withUpstreamSlot(fn, limit, instance, signal)` 先等待 QPS 窗口，再获取全局信号量；未传实例或实例非百度时跳过 QPS。页面提交与设置页测试翻译传实例，因此受限；数据面 `ST_TRANSLATE_BATCH` 保留路径按段取名额时不传实例，不经过 QPS 门控。
- 页面提交取提交时实例快照的 `qps`，测试翻译取当前实例的 `qps`（1–100 整数，默认 1）；每个百度实例一条串行链 + 滑动 1 秒窗口，批量请求按 1 次计。等待不占全局并发名额，但计入提交超时；QPS 状态只在后台内存，不持久化。
- 日志：`qps.wait`（debug：`instanceId` / `qps` / `waitMs` / `pending`）、`qps.reject`（debug：`instanceId` / `qps` / `reason: 'cancelled'`）。

### 取消

| 操作 | 排队中 | 执行中 | 已完成 |
| ---- | ------ | ------ | ------ |
| `ST_CANCEL_ITEM` | 标记取消，不发帧 | abort → `ST_ITEM_ERROR(CANCELLED)` | 忽略 |
| `ST_CANCEL_BATCH` | 全部标记取消，不发帧 | abort → 当前段 `ITEM_ERROR(CANCELLED)`，其余不结算 | 保留 |
| 端口断开 | 全部丢弃，不发帧 | abort，不发帧 | 保留（页面内存随页面销毁） |

取消是幂等的；取消后仍发一次 `ST_BATCH_DONE` 作为终态，`cancelled` 为未结算段数。

### 批超时

- 计时器在批次创建时启动：OpenAI `AI_TIMEOUT_MS.batchTotal`（180 秒），百度 `BAIDU_TIMEOUT_MS.batch`（30 秒）。
- 到期：中止当前段，所有未结算段（含未开始的段）以 `ST_ITEM_ERROR(NETWORK, BATCH_TIMEOUT)` 结算，然后回 `ST_BATCH_DONE`。
- 未开始的段可能没有对应的 `ST_ITEM_START`，客户端按 `requestId`/`itemId` 结算。

## 5. 错误映射

| 场景 | 错误码 |
| ---- | ------ |
| 载荷/字段/语言/单段超长/在途超限/重复请求 | `OTHER`（单段超长为 `TEXT_TOO_LONG`） |
| 页面通道未连接 | `NETWORK`（`NOT_CONNECTED`） |
| 缺实例、凭据不完整、实例停用/无效/类型不支持、endpoint 未授权 | `CONFIG`（提示按原因细化；百度缺凭据为「APPID 或密钥未配置完整」） |
| 鉴权、额度（来自 A3） | `AUTH` |
| 限流（来自 A3） | `RATE_LIMIT` |
| 网络、超时、流中断、批超时 | `NETWORK` |
| 百度文本超长（单段 > 4800 UTF-8 字节） | `OTHER`（`TEXT_TOO_LONG`） |
| 批量结果与输入不对齐 | `BATCH_ALIGN`（未结算 group ≥ 2 时先二分拆批；单段仍失败才标 `BATCH_ALIGN`，只影响未解析段） |
| 多段批某段空译文 | `OTHER`「引擎返回空译文」 |
| 用户取消 | `CANCELLED` |

网关只回传错误；重试由 A3 队列在同一实例内执行；A2 负责二分拆批、百度 QPS 门控与标签页关闭清理，不切换实例。

## 7. 边界情况

- 报文不是对象、类型未知、`payload` 缺失：回 `ST_BATCH_DONE`（`INVALID_MESSAGE`）。
- 数据面同端口在途批次重名：`DUPLICATE_REQUEST`；批次结束后同名可复用。页面提交按 `requestId` 去重，结束后同样可复用。
- 一个提交/批次失败不影响其它提交/批次；同一端口最多 4 个数据面在途批次。
- 端口发送失败（已断开）按断线处理，清理该端口并中止在途请求；页面提交的帧发送失败即视为该连接已断开。
- 网关不读取 `storage.session`，不写 `storage.local` / `storage.sync`；缓存只走 A4 的 IndexedDB。
- 命中或订阅时端口已断开：不发帧（该连接的提交已被清理）。
- 同 key 在途复用只在当前 Service Worker 内存中；SW 回收后同一文本可能再次调用上游。
- 旧页面（扩展更新前注入的内容脚本）可能不带 `domain`：按空串处理，不阻断翻译。
- 缓存命中帧可能早于提交回执：由 D5 的临时提交记录承接；提交失败时 D5 清理该记录。
- 页面提交初始化失败时逐段 `ST_ITEM_ERROR` 后再发 `ST_BATCH_DONE(ok:false)`，页面不会停在「已提交」。
- 多段批不逐字流式，段落直接收 `ST_ITEM_DONE`；单段批仍有 `ST_ITEM_DELTA`。
- 批量对齐失败先二分拆批；已解析段保留，拆到单段仍失败才把该段标 `BATCH_ALIGN`；批量空译文只失败该段。
- 取消一个 group 不让整个批次失败；全部订阅者取消时 abort job，队列立即释放名额。
- 提交超时包含 QPS 窗口、队列与重试等待；超时后未结算段以 `BATCH_TIMEOUT` 失败，pending job 不再启动。
- 百度实例：单批按 4800 UTF-8 字节切分（含段间换行），单段超 4800 字节以 `TEXT_TOO_LONG` 失败；百度无流式，单段批也不发 `ST_ITEM_DELTA`。
- QPS：同一百度实例的并发提交在 1 秒滑动窗口内排队；等待可被取消，取消后不发请求。切换当前实例只影响新提交，已在途提交沿用提交时的 `qps` 快照。
- 二分拆批不拆段、不重置 group 与共享执行；父批次标记 `split`，子批次使用新 id 重新入队，提交级 `ST_BATCH_DONE` 只在全部原始段落结算后发一次。
- 标签页关闭：`cleanupTab` 与端口断线清理幂等；连接已断开时重复调用只移除映射，不重复结束提交。
- 当前实例不可用时按原因回具体提示并拒绝整个提交；不会被其它禁用/未授权实例「顶替」成功。
- 切换当前实例只影响新提交；已在途提交使用提交时快照的实例与凭据。

## 8. 待确认问题

| 编号 | 问题 | 结论 |
