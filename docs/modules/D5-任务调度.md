## 1. 职责与边界

- 持有**页面会话**：首次点击「翻译整页」时取视口附近段落并提交；成功后监听滚动，按 200ms 防抖增量提交新出现的段落。
- 持有 **Ctrl 单段提交**：定位当前宿主，走同一个提交函数，`scope='single'`，只提交 1 段。
- 两种提交都只发 `ST_PAGE_SUBMIT`；页面不发送数据面 `ST_TRANSLATE_BATCH`，不接收逐段译文。
- 不读 storage、不写状态镜像；不直接 `console`（日志经 E4）。
- D 入口 `src/content/index.js` 导出 `getTask()`，返回当前任务或 `null`；C6 翻译测试页用它驱动同一份任务。普通网页注入不调用该钩子。
- 不负责后台执行：分批、同 key 去重、批量编码、真实译文回传、重试、备用切换、断线续传分别属 P6.2 / P6.4 / P9。

## 2. 任务数据

```js
page = {
  phase,                 // idle | scanning | submitting | submitted | error
  targetLang, traceId,
  requestId,             // 最近一次提交的 's-…'
  submittedHosts,        // Set<hostId>：本会话成功提交的段落
  attemptedHosts,        // Set<hostId>：本会话已尝试提交的段落（成功或失败），滚动去重
  inFlightHosts,         // Set<hostId>：正在提交的段落
  sessionToken,          // 递增令牌：重新触发/清除后旧扫描与旧响应作废
  startedAt, lastError,
}

scrollTimer              // 200ms 防抖计时器
scrollBound              // 是否已安装 window scroll 监听
scrolling                // 是否正在扫描滚动增量
scrollPending            // 扫描期间又发生滚动，结束后补一次
```

- `status()` 返回 `{ ok: true, data: { phase, total } }`，`total` 为 `submittedHosts.size`（本会话已成功提交的段落数）。
- 页面只保存 hostId 集合与当前请求标识，不保存段落正文、DOM 队列、批次表或译文。
- 不写 `storage.session` / `storage.local` / `storage.sync`；状态镜像与进度归 P7。

## 3. 提交状态机

| 状态 | 含义 | 进入条件 | 离开 |
| ---- | ---- | -------- | ---- |
| `idle` | 没有页面会话 | 初始、清除后、视口附近没有段落 | 开始提交 |
| `scanning` | 正在扫描视口附近段落 | `ST_START` | 扫描完成 / 扫描失败 |
| `submitting` | 已发出首次 `ST_PAGE_SUBMIT`，等待回执 | 扫描出至少一个段落 | 回执成功 / 失败 |
| `submitted` | 首次提交成功，页面会话与滚动监听生效 | 回执 `accepted: true` | 重复触发 / 清除 |
| `error` | 首次扫描或首次提交失败 | 扫描异常、首次提交失败 | 重复触发 / 清除 |

- 滚动增量提交不改变 `phase`：成功仍为 `submitted`；失败也保持 `submitted`，只把当前批标错。
- 段落状态只有三种可见结果：`submitting`（正在提交…）、`submitted`（已提交，等待翻译）与 `error`（提交失败：…）。
- 扫描期间再次触发直接返回当前 `phase`；`sessionToken` 让清除后迟到的扫描结果作废。

## 4. 统一提交载荷与回执

```js
submitParagraphs({ scope, paragraphs, targetLang, traceId })
  requestId = 's-…'
  payload = { requestId, traceId?, scope, targetLang?, domain, viewport, paragraphs: [...] }
  response = await chrome.runtime.sendMessage({ type: 'ST_PAGE_SUBMIT', payload })
```

载荷：

```json
{
  "type": "ST_PAGE_SUBMIT",
  "payload": {
    "requestId": "s-…",
    "traceId": "t-…",
    "scope": "page",
    "targetLang": "zh",
    "domain": "example.com",
    "viewport": { "width": 1280, "height": 800 },
    "paragraphs": [
      { "index": 0, "hostId": "h1", "text": "Hello", "context": "" },
      { "index": 1, "hostId": "h2", "text": "World", "context": "Hello" }
    ]
  }
}
```

- `scope`：`page`（整页首次或滚动增量）或 `single`（Ctrl 单段）；`single` 时 `paragraphs` 恰好 1 段。
- `index` 是本次提交内的数组序号，从 0 开始；`hostId` 是宿主上的 `data-st-host`，用于滚动去重与页面核对。
- `context` 是本次提交内上一段原文，截断到 `MAX_CONTEXT_CHARS`（400）；第一段不带该字段，不保证跨提交连续。
- `domain` 只取 `location.hostname`（`normalizeDomain` 归一），不带协议、端口、路径与查询串。
- `viewport` 为提交时的视口尺寸，只用于日志定位。
- 不携带原文以外的页面数据：无 HTML、无选择器列表、无完整 URL、无密钥、无模型。

回执：

```json
{
  "ok": true,
  "data": {
    "accepted": true,
    "requestId": "s-…",
    "scope": "page",
    "paragraphs": 12,
    "chars": 345
  }
}
```

- 只有 `ok: true` 且 `accepted: true` 视为成功；后台只做形状校验、计数、逐段日志并回执，不查缓存、不调用引擎、不返回译文。
- 失败时保留后台返回的错误码与消息，页面用它显示提示；不自动重试。

## 5. 页面会话与滚动增量

```text
start({ targetLang, traceId }):
  if phase in (scanning, submitting): return status()
  sessionToken += 1; token = sessionToken
  stopScroll(); renderer.clearAll()
  submittedHosts / attemptedHosts / inFlightHosts / requestId / lastError 清空
  phase = 'scanning'; startedAt = now()
  paragraphs = await scan({ logger })
  if token != sessionToken: return status()
  paragraphs 为空: phase = 'idle'; return status()
  phase = 'submitting'
  提交 scope='page'（全部段落）
  失败: 逐段 error；phase = 'error'；返回错误
  成功: 逐段 submitted；submittedHosts / attemptedHosts 加入 hostId；phase = 'submitted'
        installScroll(); log page.submit
```

```text
onScroll():
  phase != 'submitted': 返回
  scrolling: scrollPending = true; 返回
  重置 200ms 防抖计时器

runScrollSubmit():
  phase != 'submitted': 返回
  scrolling = true; token = sessionToken
  paragraphs = await scan({ logger })
  if token != sessionToken: return
  fresh = hostId 不在 attemptedHosts 且不在 inFlightHosts 的段落
  if fresh 为空: return
  逐段 showSubmitting；提交 scope='page'
  if token != sessionToken: 清理 inFlight; return
  fresh 的 hostId 加入 attemptedHosts
  成功: 逐段 submitted；submittedHosts 加入 hostId；log page.submit / page.scroll
  失败: 逐段 error；log page.error；页面会话保持 submitted
  scrolling = false
  if scrollPending: scrollPending = false; 重置防抖
```

- 首次提交成功后才安装滚动监听；首次失败不安装。
- 滚动增量只提交未尝试过、也不在途的 `hostId`；失败批记入 `attemptedHosts`，后续滚动不自动重试，重新点「翻译整页」才重试。
- 滚出视口的已提交标记不撤销；清除或重新触发才移除。
- 不做 `MutationObserver`；动态插入的内容只有在下一次滚动防抖或重新触发时才会被扫描到。

## 6. 重复触发、清除与生命周期

- 任意状态再次点「翻译整页」：
  1. `sessionToken += 1`，停止滚动监听、清除防抖计时器；
  2. `renderer.clearAll()` 清除本页全部标记（含 Ctrl 单段标记与失败态）；
  3. 清空 `submittedHosts` / `attemptedHosts` / `inFlightHosts` / `requestId`；
  4. 重新扫描视口附近段落并提交；成功后重新安装滚动监听。
- 扫描或首次提交进行中再次触发：返回当前 `phase` 与 `total`，不重复提交。
- 视口附近没有段落：清除旧标记后转 `idle`，返回 `total: 0`，不发送消息、不安装滚动监听。
- `ST_CLEAR`：停止滚动监听与计时器，`sessionToken += 1`，清空会话数据，`renderer.clearAll()`，`phase = 'idle'`；返回 `{ ok: true, data: { removed } }`。`data-st-host` 标记保留。
- `pagehide`：停止滚动监听、清除防抖计时器、关闭桥；不清除页面标记。
- `pageshow` 且 `persisted`：重新连接桥；若页面会话仍是 `submitted`，重新安装滚动监听。
- 扩展上下文失效（`chrome.runtime.sendMessage` 抛错或桥 `closed`）：停止页面会话，`phase = 'error'`，在途段落显示「提交失败：扩展已重新加载，请刷新页面」；不自动重试。

## 7. Ctrl 单段

| 宿主当前状态 | 行为 | 返回动作 |
| ------------ | ---- | -------- |
| `submitted` / `error` | 移除该段标记 | `hidden` |
| `submitting` | 忽略重复触发，保持「正在提交…」 | `submitting` |
| 无文字 / 无字母 | 不提交 | `no-target` |
| 其它 | 显示「正在提交…」→ 提交 `scope='single'`、1 段 → 成功「已提交」/失败「提交失败」 | `submitted` / `failed`（失败时 `ok:false` 带错误码） |

- Ctrl 单段成功时把 `hostId` 加入 `submittedHosts` / `attemptedHosts`；页面会话滚动时不会重复提交它。
- 已提交段落再次 Ctrl 只移除标记，不移除集合中的 `hostId`；后续滚动不会自动补回标记，重新点「翻译整页」才会重新提交。
- 单段不做本地长度上限判断：`ST_PAGE_SUBMIT` 只校验非空，长度上限留给 P6.2 / P6.4 的翻译批次。
- 单段提交不改变页面会话 `phase`、不安装滚动监听；失败只在当前宿主显示「提交失败」。
- 提交期间页面被「显示原文」或重新触发清空时，旧响应丢弃，不重新写标记。

## 8. 日志（E4）

| 事件 | 级别 | 内容 |
| ---- | ---- | ---- |
| `page.submit` | info | `requestId`、`scope`、段数、字符数、`accepted`、耗时（首次） |
| `page.scroll` | debug | 滚动增量新增段数 |
| `page.error` | warn | 错误码、`requestId`、`scope`、段数（扫描失败 / 首次提交失败 / 滚动增量失败） |
| `task.toggle` | info / debug | 动作（`submitted` / `hidden` / `submitting` / `no-target`）、`requestId`、文本长度 |
| `task.error` | warn | 单段提交失败的错误码 |
| `task.cancel` | info | 清除的标记数 |
| `segment.skip` | debug | 跳过原因（无文字 / 无字母） |

- `scan.start` / `scan.done` / `scan.limit` / `scan.error` 由 D1 输出（logger 由本模块注入）。
- 页面侧只输出 `page.submit` / `page.scroll` / `page.error`；逐段 `page.item` 由后台 A1 在接收 `ST_PAGE_SUBMIT` 时输出。
- 不记录原文全文、上下文、完整 URL、key 哈希与密钥。

## 9. 边界与已知限制

- 不监听 `MutationObserver`；动态内容与无限滚动追加需要滚动防抖或重新触发才会被扫描。
- 滚动监听只在页面会话 `submitted` 期间生效；清除、重新触发或页面卸载后停止。
- 扫描无法被真正中止：清除或重新触发只让旧结果失效（`sessionToken`），旧扫描仍会跑完。
- 一次性提交不受协议批次上限（12 段 / 12000 字符）约束，只受 `MAX_PAGE_PARAGRAPHS`（5000）约束；分批与并发归后台。
- 提交失败不自动重试、不切备用；首次失败需重新触发，滚动增量失败需重新触发。
- 视口判定依赖 `getBoundingClientRect`；jsdom 测试必须注入 `inViewport`。
- 混合内容容器（裸文字 + 块级子元素）中的裸文字不单独成段，与 P4 取舍一致。
- 不写状态镜像，弹窗拿不到实时进度（P7）。
