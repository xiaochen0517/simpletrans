## 1. 职责与边界

- 持有**页面会话**：首次点击「翻译整页」时取视口附近段落并提交；成功后监听滚动，按 200ms 防抖增量提交新出现的段落。
- 持有 **Ctrl 单段提交**：定位当前宿主，走同一个提交函数，`scope='single'`，只提交 1 段。
- 两种提交都只发 `ST_PAGE_SUBMIT`；页面不发送数据面 `ST_TRANSLATE_BATCH`。
- 提交前先登记临时提交记录（状态 `submitting`），让早到的命中帧可按 `requestId + itemId` 路由；提交成功后把仍处于 `submitting` 的段落推进为「已提交」，提交失败把未结算段落标错并清理该临时记录。
- 结果来源是后台 D4 帧：`ST_ITEM_START` / `ST_ITEM_DELTA` / `ST_ITEM_DONE` / `ST_ITEM_ERROR` 按 `requestId + itemId` 路由到对应段落渲染；`ST_BATCH_DONE` 只记日志，不改变段落状态。
- 不读 storage、不写状态镜像；不直接 `console`（日志经 E4）。
- D 入口 `src/content/index.js` 导出 `getTask()`，返回当前任务或 `null`；C6 翻译测试页用它驱动同一份任务。普通网页注入不调用该钩子。
- 不负责后台执行：缓存、分组、切批、同 key 去重、批量编码、真实译文生成、重试、备用切换、断线续传分别属 P6.3 / P6.4 / P9。

## 2. 任务数据

```js
page = {
  phase,                 // idle | scanning | submitting | submitted | error
  targetLang, traceId,
  requestId,             // 最近一次提交的 's-…'
  submittedHosts,        // Set<段落id>：本会话成功提交的段落
  attemptedHosts,        // Set<段落id>：本会话已尝试提交的段落（成功或失败），滚动去重
  inFlightHosts,         // Set<段落id>：正在提交的段落
  submissions,           // Map<requestId, { requestId, scope, status, token, epoch, startedAt, items }>
  registry,              // Map<段落id, { host, text }>：结果帧定位宿主
  latestRequest,         // Map<段落id, requestId>：该段最近一次提交（旧帧丢弃依据）
  sessionToken,          // 递增令牌：重新触发/清除后旧扫描、回执与结果帧作废
  startedAt, lastError,
}

submission = {
  requestId, scope,
  status,                // submitting | submitted | error
  token,                 // 提交时的 sessionToken
  epoch,                 // 提交时的 labelEpoch
  startedAt,
  items,                 // Map<段落id, { host, text, state, buffer }>
                         // state: submitting | submitted | loading | streaming | done | error
}

flushTimers              // Map<段落id, 计时器>：增量合并刷新（DISPLAY_UPDATE_THROTTLE_MS）
scrollTimer              // 200ms 防抖计时器
scrollBound              // 是否已安装 window scroll 监听
scrolling                // 是否正在扫描滚动增量
scrollPending            // 扫描期间又发生滚动，结束后补一次
```

- `status()` 返回 `{ ok: true, data: { phase, total } }`，`total` 为 `submittedHosts.size`，按原始段落计数：同文本段落各计一段，后台按 key 合并 group 不影响页面计数。
- 页面只保存段落 id、提交记录、注册表与结果状态，不保存 DOM 队列、批次表；`items.buffer` 只保存当前段的流式累计文本。
- 不写 `storage.session` / `storage.local` / `storage.sync`；状态镜像与进度归 P7。

## 3. 提交状态机

| 状态 | 含义 | 进入条件 | 离开 |
| ---- | ---- | -------- | ---- |
| `idle` | 没有页面会话 | 初始、清除后、视口附近没有段落 | 开始提交 |
| `scanning` | 正在扫描视口附近段落 | `ST_START` | 扫描完成 / 扫描失败 |
| `submitting` | 已开始首次 `ST_PAGE_SUBMIT`（提交前已登记临时记录），等待回执 | 扫描出至少一个段落 | 回执成功 / 失败 |
| `submitted` | 首次提交成功，页面会话与滚动监听生效 | 回执 `accepted: true` | 重复触发 / 清除 |
| `error` | 首次扫描或首次提交失败 | 扫描异常、首次提交失败 | 重复触发 / 清除 |

- 滚动增量提交与结果帧都不改变 `phase`：成功仍为 `submitted`；提交失败也保持 `submitted`，只把当前批标错；翻译失败只影响该段。
- 段落可见状态有六种：`submitting`（正在提交…）、`submitted`（已提交，等待翻译）、`loading`（翻译中…）、`streaming`（流式文本）、`done`（译文）与 `error`（提交失败 / 翻译失败）。
- 扫描期间再次触发直接返回当前 `phase`；`sessionToken` 让清除后迟到的扫描结果作废。

## 4. 统一提交载荷与回执

```js
submitBatch(scope, paragraphs, traceId)
  requestId = 's-…'
  registerSubmission(requestId, scope, paragraphs, 'submitting')   // 先登记临时记录
  payload = { requestId, traceId?, scope, targetLang?, domain, viewport, paragraphs: [...] }
  response = await chrome.runtime.sendMessage({ type: 'ST_PAGE_SUBMIT', payload })
```

载荷：

```json
{
  "type": "ST_PAGE_SUBMIT",
  "payload": {
    "requestId": "s-…",
    "traceId": "t-…",
    "scope": "page",
    "targetLang": "zh",
    "domain": "example.com",
    "viewport": { "width": 1280, "height": 800 },
    "paragraphs": [
      { "index": 0, "hostId": "h3f9c2a-1", "text": "Hello" },
      { "index": 1, "hostId": "h3f9c2a-2", "text": "World" }
    ]
  }
}
```

- `scope`：`page`（整页首次或滚动增量）或 `single`（Ctrl 单段）；`single` 时 `paragraphs` 恰好 1 段。
- `index` 是本次提交内的数组序号，从 0 开始，只用于日志与人工核对，不参与结果关联。
- `hostId` 是 D1 分配的页面内唯一段落 id（`h<实例标记>-<序号>`），同时作为结果帧的 `itemId`；用于滚动去重、注册表定位与页面核对。
- 每段只有 `index` / `hostId` / `text`，不携带上下文。
- `domain` 只取 `location.hostname`（`normalizeDomain` 归一），不带协议、端口、路径与查询串。
- `viewport` 为提交时的视口尺寸，随提交透传；当前不参与后台缓存、分组与切批。
- 不携带原文以外的页面数据：无 HTML、无选择器列表、无完整 URL、无密钥、无模型。

回执：

```json
{
  "ok": true,
  "data": {
    "accepted": true,
    "requestId": "s-…",
    "scope": "page",
    "paragraphs": 12,
    "chars": 345
  }
}
```

- 只有 `ok: true` 且 `accepted: true` 视为提交成功；后台校验后异步执行缓存查询与翻译，命中或定稿通过 `ST_ITEM_*` 帧回传，回执本身不返回译文。
- 发送前先 `registerSubmission(...)` 登记临时提交记录（`status: 'submitting'`，段落条目状态同为 `submitting`），再 `chrome.runtime.sendMessage`；缓存命中帧可能早于回执到达，可立即按 `requestId + itemId` 路由。
- 回执成功：`completeSubmission` 把仍处于 `submitting` 的段落推进为 `submitted` 并显示「已提交」；已收到结果帧进入 `loading` / `streaming` / `done` / `error` 的段落保持当前状态。
- 回执失败或消息抛错：`failSubmission` 把未结算段落（`submitting` / `loading` / `streaming`）显示「提交失败：<message>」，取消待刷新，并清理该提交的临时记录、注册表与「最近一次提交」索引。
- 失败时保留后台返回的错误码与消息，页面用它显示提示；不自动重试。
- `total` 按原始段落计数：`submittedHosts` 以段落 id 为单位，与后台 group 数无关。

## 5. 结果帧路由

结果帧复用数据面 `ST_ITEM_*` 形状，统一入口是 `applyResultFrame(frame)`：

| 帧 | 载荷 | 处理 |
| -- | ---- | ---- |
| `ST_ITEM_START` | `{ requestId, itemId }` | 段落进入 `loading`，显示「翻译中…」 |
| `ST_ITEM_DELTA` | `{ requestId, itemId, delta }` | 追加到 `items.buffer`，进入 `streaming`；按 80ms 合并刷新 |
| `ST_ITEM_DONE` | `{ requestId, itemId, text, usage }` | 取消待刷新，用 `text` 覆盖并显示定稿，进入 `done` |
| `ST_ITEM_ERROR` | `{ requestId, itemId, code, message, reason? }` | 取消待刷新，显示「翻译失败：<message>」，进入 `error` |

```text
applyResultFrame(frame):
  type 不在 ST_ITEM_* 或帧为空: 返回 false
  requestId / itemId 不是字符串: 返回 false
  submission = submissions[requestId]
  没有记录: 丢弃（no-submission）
  submission.token != sessionToken 或 submission.epoch != labelEpoch: 丢弃（stale）
  latestRequest[itemId] != requestId: 丢弃（superseded）
  item = submission.items[itemId]
  没有条目: 丢弃（no-item）
  host = registry[itemId].host
  没有宿主或宿主已断开: 注销注册表条目，丢弃（no-host）
  START: item.state != done 时置 loading 并 showLoading
  DELTA: item.state != done 时置 streaming、累加 buffer、安排合并刷新
  DONE:  取消刷新，置 done，用 text 覆盖并 showDone
  ERROR: 取消刷新，置 error，showError
  记 page.result（只含 requestId / itemId / 类型 / 状态）
```

- 丢弃时记 `page.result.dropped`（debug），只带 `requestId` / `itemId` / 原因，不带文本。
- 允许的异常序列：`DONE` 或 `DELTA` 没有前置 `START`；重复 `START`（幂等）；重复 `DONE`（后到覆盖）。
- `DONE` 之后的 `DELTA` 被忽略，不会从译文退回部分文本。
- 同一段并发多路提交时，`latestRequest` 指向最后一次提交，先前提交的迟到帧被丢弃。
- 结果帧由 `content/index.js` 的 `handleFrame` 把 D4 的 `ST_ITEM_*` 转发到 `applyResultFrame`；测试可直接调用同一函数驱动状态机。

## 6. 页面会话与滚动增量

```text
start({ targetLang, traceId }):
  if phase in (scanning, submitting): return status()
  sessionToken += 1; token = sessionToken
  stopScroll(); stopResultPipeline(); renderer.clearAll()
  submissions / registry / latestRequest / 已提交/已尝试/在途集合 / requestId / lastError 清空
  phase = 'scanning'; startedAt = now()
  paragraphs = await scan({ logger })
  if token != sessionToken: return status()
  paragraphs 为空: phase = 'idle'; return status()
  phase = 'submitting'
  登记临时提交记录（submitting）→ 提交 scope='page'（全部段落）
  失败: failSubmission（未结算段落标错 + 清理临时记录）；phase = 'error'；返回错误
  成功: completeSubmission（submitting → submitted）；phase = 'submitted'
        installScroll(); log page.submit
```

```text
onScroll():
  phase != 'submitted': 返回
  scrolling: scrollPending = true; 返回
  重置 200ms 防抖计时器

runScrollSubmit():
  phase != 'submitted': 返回
  scrolling = true; token = sessionToken
  paragraphs = await scan({ logger })
  if token != sessionToken: return
  fresh = 段落 id 不在 attemptedHosts 且不在 inFlightHosts 的段落
  if fresh 为空: return
  逐段 showSubmitting；登记临时提交记录（submitting）→ 提交 scope='page'
  if token != sessionToken: 清理 inFlight; return
  fresh 的段落 id 加入 attemptedHosts
  成功: completeSubmission（submitting → submitted）
        log page.submit / page.scroll
  失败: failSubmission（未结算段落标错 + 清理临时记录）；log page.error；页面会话保持 submitted
  scrolling = false
  if scrollPending: scrollPending = false; 重置防抖
```

- 首次提交成功后才安装滚动监听；首次失败不安装。
- 滚动增量只提交未尝试过、也不在途的段落 id；失败批记入 `attemptedHosts`，后续滚动不自动重试，重新点「翻译整页」才重试。
- 滚出视口的已提交标记与译文不撤销；清除或重新触发才移除。
- 不做 `MutationObserver`；动态插入的内容只有在下一次滚动防抖或重新触发时才会被扫描到。

## 7. 重复触发、清除与生命周期

- 任意状态再次点「翻译整页」：
  1. `sessionToken += 1`，停止滚动监听、清除防抖计时器、停止增量刷新计时器；
  2. `renderer.clearAll()` 清除本页全部标记、流式文本与译文（含 Ctrl 单段标记与失败态）；
  3. 清空 `submittedHosts` / `attemptedHosts` / `inFlightHosts` / `submissions` / `registry` / `latestRequest` / `requestId`；
  4. 重新扫描视口附近段落并提交；成功后重新安装滚动监听。
- 扫描或首次提交进行中再次触发：返回当前 `phase` 与 `total`，不重复提交。
- 视口附近没有段落：清除旧标记后转 `idle`，返回 `total: 0`，不发送消息、不安装滚动监听。
- `ST_CLEAR`：停止滚动监听与计时器、停止增量刷新，`sessionToken += 1`，清空会话数据，`renderer.clearAll()`，`phase = 'idle'`；返回 `{ ok: true, data: { removed } }`。`data-st-host` 标记保留。
- `pagehide`：停止滚动监听、清除防抖计时器、停止增量刷新、关闭桥；不清除页面标记。
- `pageshow` 且 `persisted`：重新连接桥；若页面会话仍是 `submitted`，重新安装滚动监听。已丢失的流式输出不重放，该段停在最后一帧的状态。
- 扩展上下文失效（`chrome.runtime.sendMessage` 抛错或桥 `closed`）：桥记录「扩展已重新加载，请刷新页面」；提交中的段落按提交失败标错；不自动重试。

## 8. Ctrl 单段

| 宿主当前状态 | 行为 | 返回动作 |
| ------------ | ---- | -------- |
| `done` / `error` | 移除该段标记与译文，注销注册表条目 | `hidden` |
| `loading` / `streaming` / `submitting` | 忽略重复触发，保持当前进行中显示 | `submitting` |
| `submitted` | 移除该段标记，注销注册表条目 | `hidden` |
| 无文字 / 无字母 | 不提交 | `no-target` |
| 其它 | 显示「正在提交…」→ 提交 `scope='single'`、1 段 → 成功后「已提交」并开始回显 / 失败「提交失败」 | `submitted` / `failed`（失败时 `ok:false` 带错误码） |

- Ctrl 单段先登记临时提交记录；成功时把段落 id 加入 `submittedHosts` / `attemptedHosts`，页面会话滚动时不会重复提交它。
- 已提交段落再次 Ctrl 只移除标记，不移除集合中的段落 id；后续滚动不会自动补回标记，重新点「翻译整页」才会重新提交。
- 单段不做本地长度上限判断：`ST_PAGE_SUBMIT` 只校验非空；分组、切批与批次字符上限由后台按实例参数处理，单段超过 4000 字符由后台以 `TEXT_TOO_LONG` 判错。
- 单段提交不改变页面会话 `phase`、不安装滚动监听；失败只在当前宿主显示「提交失败」。
- 提交或回显期间页面被「显示原文」或重新触发清空时，旧回执与旧结果帧丢弃，不重新写标记。

| `page.result.error` | warn | `requestId`、`itemId`、错误码 |

- 不记录原文全文、上下文、译文内容、完整 URL、key 哈希与密钥。

## 10. 边界与已知限制

- 不监听 `MutationObserver`；动态内容与无限滚动追加需要滚动防抖或重新触发才会被扫描。
- 滚动监听只在页面会话 `submitted` 期间生效；清除、重新触发或页面卸载后停止。
- 扫描无法被真正中止：清除或重新触发只让旧结果失效（`sessionToken`），旧扫描仍会跑完。
- 结果帧找不到宿主（页面框架替换节点、标记被手动删除）时丢弃；重扫给新节点分配新段落 id，视为新段落。
- 一次性提交不受协议批次上限（12 段 / 12000 字符）约束，只受 `MAX_PAGE_PARAGRAPHS`（5000）约束；单段长度、分批与并发归后台。
- 提交失败不自动重试、不切备用；首次失败需重新触发，滚动增量失败需重新触发；翻译失败只影响该段，重新触发可重试。
- 视口判定依赖 `getBoundingClientRect`；jsdom 测试必须注入 `inViewport`。
- 混合内容容器（裸文字 + 块级子元素）中的裸文字不单独成段，与 P4 取舍一致。
- 不写状态镜像，弹窗拿不到实时进度（P7）。
- 结果来源是后台 D4 帧；页面暂不发送 `ST_CANCEL_BATCH` / `ST_CANCEL_ITEM`，真实取消由 P7 接入。
