## 1. 职责与边界

- 把提交与译文状态以行内容器内嵌到被翻译节点末尾，支持正在提交、已提交、翻译中、流式、译文与失败六种显示状态。
- 支持单段隐藏与清除全部；隐藏只移除状态容器，原文与宿主标记不动。
- 结果来源是后台 D4 帧：D5 把 `ST_ITEM_START` / `ST_ITEM_DELTA` / `ST_ITEM_DONE` / `ST_ITEM_ERROR` 按 `requestId + itemId` 路由后调用渲染方法；增量按 D5 的 80ms 合并刷新，定稿立即覆盖。缓存命中只有「START → DONE」（无增量）；共享结果中 owner 段可能收到增量，其它订阅者只收到「START → DONE」。
- 不提取文本、不判断段落、不发请求、不读 storage；这些分别属于 D1、D2、D5。
- 不直接写日志；状态变化由 D5 记录。

## 2. DOM 契约

状态容器固定为 `<font>`，作为宿主最后一个子节点；容器内再放一个 `<font>` 承载状态文本，并在容器创建时创建一次 `<span role="button" tabindex="0" data-st-retry aria-label="重新翻译此段">刷新</span>`。刷新元素默认 `hidden`，只有 `data-st-state="error"` 时显示。宿主可以是任意标签（`p`、`span`、`button`、`a`、`code` 等）：

```html
<!-- 段落：宿主计算样式为块级 -->
<p data-st-host="h3f9c2a-1">Original <strong>text</strong>.
  <font data-st-translation=""
        data-st-for="h3f9c2a-1"
        data-st-state="done"
        data-st-mode="block"
        dir="auto"><br><font>这是一段示例译文。</font></font>
</p>

<!-- 行内 / inline-block 宿主：流式中 -->
<span data-st-host="h3f9c2a-2">原文<font data-st-translation=""
      data-st-for="h3f9c2a-2"
      data-st-state="streaming"
      data-st-mode="inline"
      dir="auto">&nbsp;&nbsp;<font>部分译文</font></font></span>

<!-- 按钮宿主：翻译失败 -->
<button data-st-host="h3f9c2a-3">Submit<font data-st-translation=""
        data-st-for="h3f9c2a-3"
        data-st-state="error"
        data-st-mode="inline"
        dir="auto">&nbsp;&nbsp;<font>翻译失败：网络连接失败</font><span role="button" tabindex="0" data-st-retry="" aria-label="重新翻译此段">刷新</span></font></button>
```

| 标记 | 位置 | 含义 |
| ---- | ---- | ---- |
| `data-st-host` | 原文节点 | D1 分配的段落 id（`h<实例标记>-<序号>`） |
| `data-st-translation` | 外层容器 | 存在即表示该宿主有提交或译文显示 |
| `data-st-for` | 外层容器 | 指向段落 id，供悬停与清理使用 |
| `data-st-state` | 外层容器 | `submitting` / `submitted` / `loading` / `streaming` / `done` / `error` |
| `data-st-mode` | 外层容器 | `block`（宿主块级，`<br>` 换行）/ `inline`（宿主行内，`&nbsp;&nbsp;` 分隔） |
| `dir` | 外层容器 | 固定 `auto`，兼容 RTL 目标语言 |
| `data-st-retry` | 刷新元素 | 容器创建时创建一次，默认 `hidden`；仅 `data-st-state="error"` 时显示，非错误态不响应点击/键盘 |

- 状态文本只写入内层 `<font>` 的 `textContent`，禁止 `innerHTML`；`<br>` 与分隔空格是固定结构，不来自页面或模型输出。
- 同一宿主重复显示时复用同一个容器，不叠加第二个。
- 容器被页面脚本删除后，下一次更新重建；宿主已从文档移除时删除容器并清掉状态。

## 3. 插入位置与格式

1. 永远 `host.appendChild(container)`：状态是宿主最后一个子节点。
2. 模式由宿主计算样式决定，不按标签名判断：
   - `block` / `flow-root` / `list-item` / `table` / `table-cell` / `table-caption` / `flex` / `grid` 等块级容器 → `data-st-mode="block"`：容器内先放 `<br>`，再放内层 `<font>`；状态另起一行，不增加外边距。
   - `inline` / `inline-block` / `inline-flex` / `inline-grid` / `inline-table` / `ruby` 等行内级 → `data-st-mode="inline"`：容器内先放两个 U+00A0，再放内层 `<font>`；状态与原文同一行，以两个空格分隔。
   - `display: contents` 时向上找到实际参与布局的祖先，再用该祖先的 `display` 判断。
3. 容器保持 `display: inline`，`data-st-mode` 只记录宿主布局，不代表容器自身 `display`。
4. 不增加 `margin` / `padding` / `border`；段落间距、列表标记、表格边框、缩进与悬挂缩进保持原样。

已知限制：

- 宿主是 flex / grid 时，容器会成为 flex / grid 项目，`<br>` 只在项目内部换行，可能无法与原文上下排列；P4 不引入站点规则，由人工验收覆盖。
- 页面用 `!important` 强制 `font` 样式时，`all: unset` 也可能被覆盖。
- 标题宿主的标记继承标题字号，这是「样式随宿主」的预期结果。
- 内嵌后宿主 `textContent` / `innerText` 包含状态文本；D1 提取已排除，页面脚本读取与选中复制会看到标记（复制行为已确认接受）。

## 4. 状态与样式

| 状态 | 容器内容（内层 `<font>` 为状态文本） | 样式 |
| ---- | ------------------------------------ | ---- |
| `submitting` | 块级宿主：`<br><font>正在提交…</font>`；行内宿主：`&nbsp;&nbsp;<font>正在提交…</font>` | 不透明度 0.55 |
| `submitted` | 内层 `<font>` 为 `已提交，等待翻译` | 不透明度 0.7、斜体 |
| `loading` | 内层 `<font>` 为 `翻译中…` | 不透明度 0.55 |
| `streaming` | 内层 `<font>` 为已累计的流式文本 | 不透明度 0.55 |
| `done` | 内层 `<font>` 为最终译文 | 不透明度 0.95、正体 |
| `error` | 内层 `<font>` 为 `提交失败：<提示>` 或 `翻译失败：<提示>`，后接 `<span role="button" tabindex="0" data-st-retry>刷新</span>` | 不透明度 0.8、斜体、点线下划线；刷新默认灰黑无下划线，hover 下划线 + indigo |

```css
[data-st-translation] {
  all: unset;
  display: inline;
  font: inherit;
  line-height: inherit;
  color: inherit;
  text-align: inherit;
  white-space: inherit;
  overflow-wrap: anywhere;
  opacity: 0.92;
  cursor: text;
}

[data-st-translation] > font {
  all: unset;
  font: inherit;
  color: inherit;
  white-space: inherit;
}

[data-st-retry] {
  all: unset;
  display: inline;
  margin-left: 0.5em;
  color: #4b5563;
  font: inherit;
  line-height: inherit;
  cursor: pointer;
  user-select: none;
}

[data-st-retry][hidden] {
  display: none;
}

[data-st-retry]:hover {
  color: #4f46e5;
  text-decoration: underline;
}

[data-st-retry]:focus-visible {
  outline: 2px solid #4f46e5;
  outline-offset: 2px;
}
```

- 只用 `data-st-*` 选择器，不命中页面原有元素。
- `[data-st-retry]` 的 `all: unset` 会清掉 `display`，因此必须有 `[data-st-retry][hidden] { display: none; }`，否则 `hidden` 属性失效。
- 正文颜色、字体、字号、字重、行高、字距、对齐与 `white-space` 全部继承宿主；「刷新」按钮例外，使用固定色 `gray-600`（`#4b5563`）与 hover/focus `indigo-600`（`#4f46e5`）；这是 HyperUI 调色板在注入样式中的固定映射，深色页面的可读性由人工验收覆盖。
- 错误态不依赖颜色区分；提交中只降低不透明度；「刷新」按钮默认无下划线，hover 才出现下划线。

## 5. 接口

```js
const renderer = createRenderer({ document, onRetry: (host) => task.retry(host) });
renderer.showSubmitting(host);            // 正在提交…
renderer.showSubmitted(host, text?);      // 已提交，等待翻译
renderer.showLoading(host);               // 翻译中…
renderer.update(host, text);              // 流式累计文本
renderer.showDone(host, text);            // 定稿译文
renderer.showSubmitError(host, message);  // 提交失败：…
renderer.showError(host, message);        // 翻译失败：…
renderer.remove(host);                    // 隐藏单段，移除整个容器（含 br / 分隔空格）
renderer.clearAll();                      // 清除全部，返回移除数量
renderer.getState(host);                  // submitting | submitted | loading | streaming | done | error | null
renderer.has(host);

export const RETRY_ATTR = 'data-st-retry'; // CSS 与测试共用
```

- 渲染方法要求宿主已有 `data-st-host`；`data-st-for` 直接读该属性。
- `showSubmitError` 对空消息回退为「提交失败，请重试」；`showError` 对空消息回退为「翻译失败，请重试」。
- 刷新元素在容器创建时创建一次，默认 `hidden`，只有 `state === 'error'` 时显示；点击或 Enter/Space 都先 `preventDefault()` + `stopPropagation()`，只调用注入的 `onRetry(host)`，不触发表单提交、不导航、不冒泡到宿主按钮/链接；非错误态不响应。使用 `span[role=button]` 而不是嵌套原生 `<button>`/`<a>`，避免宿主本身是按钮/链接时的非法结构。
- 状态切换只改容器属性与内层 `<font>` 的文本，`<br>` / 分隔空格位置不变。
- `update` 与 `showDone` 都由 D5 在结果帧到达时调用：增量按 80ms 合并，定稿立即写入。

## 6. 错误与提示

| 情况 | 页面显示 |
| ---- | -------- |
| 提交中 | 正在提交… |
| 已提交 | 已提交，等待翻译 |
| 开始处理 | 翻译中… |
| 流式中 | 已累计的增量文本 |
| 定稿 | 最终译文 |
| 提交失败 | 提交失败：<后台 message> |
| 翻译失败 | 翻译失败：<错误 message> |
| 错误后点「刷新」 | 仅重新提交当前段，清除错误并显示「正在提交…」 |

- 结果来自后台 D4 帧：缓存命中为 `START → DONE`（无增量）；共享结果中 owner 段为 `START → DELTA… → DONE`，其它订阅者为 `START → DONE`。D5 按 80ms 合并增量，定稿立即覆盖。

## 7. 边界情况

- 宿主在文档外：`show*` 返回 `false`，不抛错；已有容器会被移除。
- 非错误态点击或键盘触发「刷新」不响应；刷新元素随容器复用，不叠加第二个。
- 容器被页面删除：下一次 `show*` 重建。
- 页面刷新：标记与译文不持久化，全部消失。
- 宿主文本包含状态标记：D1 的 `extractText` 排除 `[data-st-translation]` 子树，D5 不直接读 `textContent`。
- 宿主被页面框架替换：旧容器随旧节点消失；D5 按段落 id 找不到宿主时丢弃结果帧，不重建到别的段落。
- 重复 `DONE`：以后到的文本覆盖；`DONE` 后的 `DELTA` 由 D5 忽略，不会退回流式。
