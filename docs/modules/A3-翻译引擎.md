## 1. 职责与边界

- **唯一出口**：所有翻译（整页、悬停、设置页测试）都经 A3 适配器调用引擎，其它模块不得各自发请求。
- **协议**：大模型只走 OpenAI-compatible Chat Completions（`baseUrl + path`，默认 `/chat/completions`）；不实现 `/v1/responses`、旧 `/v1/completions`、Anthropic/Gemini 原生协议、自定义响应路径与 content 数组。传统引擎只接入百度通用文本翻译（`POST` 表单、原生批量），不接入领域翻译或其它服务商。
- **单段与批量**：单段走 `translate`（OpenAI 可流式，百度无增量）；同一批次的多个段落走 `translateBatch`（OpenAI 用 JSONL、百度用换行分隔 `q`，一次请求，按段回调）。
- **队列**：批次由 A3 的全局 FIFO 队列执行，按实例 `maxConcurrency` 限制同时在途的 job 数；只对 `retryable` 错误（`NETWORK` / `RATE_LIMIT`）重试，默认最多 2 次（总尝试 3 次），等待 1 秒 / 2 秒 + 0–250ms 抖动；已产生输出、已取消、非可重试码与次数用尽都不重试；队列不持久化、不写缓存、不持有页面连接。
- 密钥与接口地址来自实例（由 E3 解析，调用方从存储读取后传入），A3 不直接读写存储；密钥不进日志、不进产物。
- 空文本、缺密钥、已取消、endpoint 非法、主机权限未授权都在调用上游前短路；批量对齐失败按 `BATCH_ALIGN` 上抛，已解析段落保留。
- 不自动重连；队列在同一实例内对网络与限流错误重试 2 次；QPS 由 A2 门控，不在适配器内实现；不提供备用切换。

## 2. 配置模型

### 2.1 类型与预设

```js
{
  type: 'openai',
  preset: 'deepseek' | 'custom',
  endpoint: { baseUrl, path, query: [{ name, value }], stream },
  auth: { type: 'bearer' | 'header' | 'query' | 'none', headerName, prefix, queryName },
  headers: [{ name, value }],
  model,
  params: {
    temperature: { enabled, value },
    topP: { enabled, value },
    maxTokens: { enabled, field, value },
    reasoning: { mode, field, value, values, budgetField, budget, toggleField, onValue, offValue },
    extra: [{ path, type, value, enabled }],
  },
}
```

- `systemPrompt` 由 P8-2 从实例读取后随实例传入；A3 只负责展开与使用。
- `apiKey` 由调用方随实例传入；A3 只读取，不读写存储。

DeepSeek 预设默认值：

| 项 | 默认值 |
| -- | ------ |
| `endpoint.baseUrl` | `https://api.deepseek.com` |
| `endpoint.path` | `/chat/completions` |
| `endpoint.stream` | `true` |
| `auth.type` | `bearer` |
| `model` | `deepseek-chat` |
| `params.temperature` | 关闭（不发送） |
| `params.topP` | 关闭（不发送） |
| `params.maxTokens` | 关闭（不发送） |
| `params.reasoning.mode` | `effort` |
| `params.reasoning.field` | `reasoning_effort` |
| `params.reasoning.values` | `off` / `low` / `medium` / `high` / `max` |
| `params.reasoning.value` | `off` |
| `params.reasoning.toggleField` | `thinking.type` |
| `params.reasoning.onValue` | `enabled` |
| `params.reasoning.offValue` | `disabled` |
| `params.extra` | `[]` |
| `headers` | `[]` |

`custom` 预设：空 `baseUrl`、空 `model`、全部生成参数关闭、`reasoning.mode = 'none'`。预设只是默认值，字段都可编辑。

### 2.2 endpoint

- `baseUrl`：HTTPS，或本地回环 HTTP（`localhost` / `127.0.0.1`）；不含账号密码、查询串与片段；可带路径前缀。
- `path`：默认 `/chat/completions`，必须以 `/` 开头，不含空白、`?` 与 `#`；可改为 deployment 等路径。
- `query`：静态查询参数列表（如 `api-version`），不放密钥；名字非空、不重复。
- `stream`：默认 `true`；`false` 时请求完整 JSON。

### 2.3 auth

| 方式 | 请求效果 |
| ---- | -------- |
| `bearer` | `Authorization: Bearer <apiKey>` |
| `header` | `<headerName>: <prefix> <apiKey>`；`prefix` 为空时只写密钥 |
| `query` | 追加查询参数 `<queryName>=<apiKey>` |
| `none` | 无认证，不需要密钥 |

- `header` 的 `headerName` 不能是 `Cookie` / `Host` / `Content-Length` / `Content-Type`；`query` 的 `queryName` 不能与静态 query 重名。

### 2.4 静态 headers

- `name` 必须是合法 HTTP token，`value` 不含控制字符；名字不重复（忽略大小写）。
- 禁止覆盖 `Authorization`、`api-key`、`x-api-key`、`Cookie`、`Host`、`Content-Length`、`Content-Type`；也不能与 `auth.headerName` 同名。
- 密钥只走 `auth`；静态 header 不放密钥。

### 2.5 model 与提示词

- `model` 自由输入，1–100 字符，不做白名单。
- `systemPrompt` 是实例级模板；A3 用 `buildSystemPrompt({ targetLang, template, mode })` 展开 `{{targetLang}}` 与 `{{outputFormat}}`；空模板回退默认模板。

### 2.6 生成参数

| 参数 | 启用时发送 | 校验 |
| ---- | ---------- | ---- |
| `temperature` | `temperature: value` | 0–2 |
| `topP` | `top_p: value` | 0–1 |
| `maxTokens` | `field: value`，field 为 `max_tokens` 或 `max_completion_tokens` | 正整数 |
| `reasoning.mode = 'none'` | 不发送 | — |
| `reasoning.mode = 'effort'` | `value === 'off'` 时只发 `toggleField: offValue`；否则发 `field: value` 与 `toggleField: onValue` | `field` 为合法点路径；`value` 在 `values` 内 |
| `reasoning.mode = 'budget'` | `budgetField: budget` | 字段合法、预算正整数 |
| `reasoning.mode = 'toggle'` | `value` 非 `off` 时发 `toggleField: onValue`，否则发 `offValue` | 字段合法、`onValue` 非空 |
| `extra` | 按点路径写入请求体 | 路径合法、不与 `messages` / `model` / `stream` 或已启用参数重复、同类型值合法 |

- 所有可选参数默认关闭；关闭即不发送，避免给不支持该参数的模型发 400。
- `extra.value` 按 `type` 转换：`string` / `number` / `boolean` / `json`；`json` 必须是合法 JSON 文本。
- `extra` 路径为点分标识符（每段 `[A-Za-z_][A-Za-z0-9_-]*`），最多 6 段；路径之间不能互为前缀。

## 3. 接口

### 3.1 适配器入口

`adapter.js`（调用方直接使用；按 `instance.type` 分发，旧实例自动映射）：

```js
translate({ text, targetLang, sourceLang, instance, onDelta, signal, fetchImpl, timeoutMs, checkPermission, salt }) → { text, usage }
translateBatch({ items, targetLang, sourceLang, instance, onItem, signal, fetchImpl, timeoutMs, checkPermission, salt }) → { usage }
```

- `instance` 可以是旧的 `type: 'deepseek'` 实例（映射后走 OpenAI）、`type: 'openai'` 或 `type: 'baidu'` 实例；未知类型抛 `TranslateError(CONFIG)`。
- OpenAI 实例的凭据字段是 `apiKey`；百度实例是 `appId` / `secretKey`；凭据均由调用方从存储读取后随实例传入。
- `sourceLang` 只供百度 `from` 使用（`auto` / `en`），OpenAI 不使用。
- `usage` 为 `{ promptTokens, completionTokens, totalTokens }` 或 `null`；百度固定 `null`。
- 失败抛 `TranslateError`（`code` + 用户可见 `message`）。

`adapters/openai.js`（P8-1；P8-2 集成与测试可直接调用）：

```js
translate({ text, targetLang, instance, onDelta, signal, fetchImpl, timeoutMs, checkPermission })
translateBatch({ items, targetLang, instance, onItem, signal, fetchImpl, timeoutMs, checkPermission })
```

- `fetchImpl`：替换全局 `fetch`，用于测试；默认 `globalThis.fetch`。
- `timeoutMs`：覆盖总超时；默认单段 `AI_TIMEOUT_MS.total`（120 秒）、批量 `AI_TIMEOUT_MS.batchTotal`（180 秒）。
- `checkPermission`：`chrome.permissions.contains` 风格函数；未授权返回 `CONFIG`，不构造/发送请求。
- 外部 `signal` 与总超时用 `AbortSignal.any` 合并；外部取消优先映射 `CANCELLED`，内部超时映射 `NETWORK`。

`adapters/baidu.js`（P8-2）：

```js
translate({ text, targetLang, sourceLang, instance, signal, fetchImpl, timeoutMs, salt }) → { text, usage: null }
translateBatch({ items, targetLang, sourceLang, instance, onItem, signal, fetchImpl, timeoutMs, salt }) → { usage: null }
signBaidu({ appId, q, salt, secretKey }) → string
normalizeBaiduText(text) → string
mapBaiduError(errorCode) → TranslateError
utf8Bytes(text) → number
```

- `salt` 可注入，默认每次随机；签名 `MD5(appid + q + salt + 密钥)` 32 位小写，`q` 使用 UTF-8 原文且先归一换行。
- 默认超时：单段 15 秒、批量 30 秒（`BAIDU_TIMEOUT_MS`）。
- 百度无流式：单段没有 `onDelta`；批量按 `trans_result` 顺序逐段 `onItem`。
- 单段超过 4800 UTF-8 字节、批量 `q` 超过 4800 字节、缺 APPID/密钥、不支持语言都在发请求前失败。

### 3.7 翻译队列

```js
createTranslationQueue({ execute, wait, random }) → {
  setConcurrency, enqueueBatch, cancelJob, dropGroup, getQueueStats,
}
```

- `execute` / `wait` / `random` 可注入，分别用于执行 job、等待与抖动；默认使用真实执行器、`setTimeout` 与 `Math.random`。
- job 可选 `maxAttempts`（默认 `RETRY_DELAYS_MS.length + 1 = 3`）、`retryDelays`（默认 `[1000, 2000]`）与 `canRetry()`。
- 只重试 `retryable` 错误（`NETWORK` / `RATE_LIMIT`）；`CANCELLED`、非可重试码、`canRetry() === false`（已产生输出）与次数用尽都不重试。
- 等待 = 退避 + `Math.floor(random() * RETRY_JITTER_MS)`；等待期间 job 仍为 running 并占用队列名额；取消会立即释放队列名额并 abort，等待结束后不再发请求。
- 重试不重置 `groups`；成功只回调一次 `onBatchDone`，最终失败只回调一次 `onBatchError`。
- 日志：`queue.retry`（info：`jobId` / `requestId` / `attempt` / `maxAttempts` / `code` / `delayMs`）、`queue.retry.skip`（debug：`jobId` / `requestId` / `code` / `reason` / `attempt`，`reason` 为 `emitted` / `cancelled` / `not-retryable`）。

## 4. 请求构造规则

- **URL**：`baseUrl` 去尾部 `/` + `path` + 静态 query；认证 query 由 `auth` 追加。只允许 HTTPS 或本地回环 HTTP；拒绝账号密码、查询串与片段。
- **Headers**：`Content-Type: application/json`；认证头；静态 headers；禁止危险 header（见 2.4）。
- **Body**：`model`；`messages: [{ role: 'system', content: 展开后的模板 }, { role: 'user', content: 原文/JSONL }]`；`stream`；启用的生成参数与 `extra`。
- 不默认发送 `stream_options`；需要 usage 时由 `extra` 添加 `stream_options.include_usage`。
- 请求体只包含 model/messages/stream/参数，不包含 URL、页面信息、上下文或密钥。
- `fetch` 使用 `redirect: 'error'`、`credentials: 'omit'`、`cache: 'no-store'`。

## 5. SSE 与非流式响应

### 5.1 SSE

- 使用 `eventsource-parser` 的 `EventSourceParserStream` 分帧：处理任意 chunk 边界、多行 `data:`、CRLF/LF、注释/`ping`、`[DONE]`；不自行按行拆分、不自行拼 `data:`。
- 末尾补两个换行，保证末帧没有结尾空行时也能派发。
- 标准事件：`choices[0].delta.content` 为字符串时累计并回调；其它字段忽略；没有 `choices` 也没有 `usage` 的事件按非标准格式失败。
- `usage` 取最后一个包含 usage 的事件，缺失为 `null`；`[DONE]` 结束，之后的事件不再处理。
- 流内 `error` 对象按统一错误码抛出；非法 JSON 按「格式不支持」失败，不部分猜译。
- 上限：单事件 1 MB、总量 16 MB、20000 事件；超限按 `OTHER` 失败。
- 取消：`AbortSignal` 中断 fetch/reader；`finally` 取消 reader；取消后不再回调。
- 不自动重连，避免重复请求与重复计费。

### 5.2 非流式

- `endpoint.stream === false` 或响应为 `application/json` 时按标准 JSON 解析。
- `choices[0].message.content` 必须是字符串；content 数组、缺少 choices、旧 completions 等返回 `OTHER`。
- `usage` 读取标准字段 `prompt_tokens` / `completion_tokens` / `total_tokens`。
- 批量 JSONL 从 `message.content` 读取完整 JSONL，交给 `batch.js` 解析对齐。

## 6. 错误映射

| 条件 | 错误码 | 提示 |
| ---- | ------ | ---- |
| 缺密钥（调用前短路） | `CONFIG` | 缺少密钥，请先在设置页配置 |
| endpoint 未填/非法 | `CONFIG` | 接口地址无效，请检查 baseUrl 与 path |
| 主机权限未授权 | `CONFIG` | 未授权访问该接口域名，请到设置页重新授权 |
| 模型/参数/header 配置非法 | `CONFIG` | 具体字段提示（如「temperature 必须是 0–2 之间的数字」） |
| HTTP 401/403 | `AUTH` | 密钥无效或鉴权失败 |
| HTTP 402 | `AUTH` | 额度不足或账户欠费 |
| HTTP 429 | `RATE_LIMIT` | 请求过于频繁，请稍后重试 |
| HTTP 5xx / 408 / 504 / 网络 / 超时 | `NETWORK` | 网络错误或请求超时 |
| HTTP 400 参数不被支持 | `CONFIG` | 请求参数不被当前模型支持，请关闭不支持的参数 |
| HTTP 404 | `CONFIG` | 接口地址无效，请检查 baseUrl 与 path |
| 响应格式非标准 | `OTHER` | 当前接口返回格式暂不支持，请使用标准 OpenAI Chat Completions |
| 空译文（单段） | `OTHER` | 引擎返回空译文 |
| 批量对齐失败 | `BATCH_ALIGN` | 批量结果与输入不对齐 |
| 取消 | `CANCELLED` | 翻译已取消 |

- 不把上游原始报文透传给页面；错误提示不含密钥、URL、请求头/体。
- 流内 error 事件按状态码或错误类型映射；已回调的增量保留，由 A2 决定该段失败。
- 批量中某段空译文不在 A3 失败，由 A2 只把该段标 `OTHER`「引擎返回空译文」。

## 7. 缓存 profile 与主机权限

- `endpointFingerprint`：`origin + baseUrl 路径前缀 + path + 非敏感静态 query`；静态 query 按键值排序；不含认证 query、密钥与 header。
- `generationProfile`：`stream` 与实际写入请求体的生成参数（键排序、忽略未启用项）。
- `generationHash`：对 `generationProfile` 做稳定序列化后 SHA-256，小写十六进制。
- `buildLLMProfile`：一次返回两个值；A2 在 cache key v3 中拼入引擎类型、`model`、`promptHash`、`promptVersion`、`batchEncodingVersion`、语言与原文。百度 profile 固定为 `baidu` / `general` / `none` / `baidu:v1` / 版本 0，不调用本模块。
- `getOriginPattern(baseUrl)`：HTTPS → `https://host/*`；本地回环 → `http://localhost/*` / `http://127.0.0.1/*`；匹配模式不带端口。实现位于 E3 `config/host-permission.js`，本模块只转出。
- `isEndpointPermitted(baseUrl, { contains })`：可注入检查函数；没有权限 API 的环境（单元测试）按已授权处理；实例资格检查由 E3 复用同一实现，实际 `chrome.permissions.request` 与 UI 由设置页负责。

## 8. 日志

- 使用 E4（`src/shared/log/`），不直接调用 `console.*`。
- OpenAI 单段与批量记录：`engine.openai.request` / `engine.openai.done` / `engine.openai.cancel` / `engine.openai.error`，数据含 `preset`、`model`、`stream`、`authType`、`reasoningMode`、`promptVersion`、`promptDefault`、`mode`，批量另带 `batchItems` 与 `encodingVersion`。
- 百度单段与批量记录：`engine.baidu.request` / `engine.baidu.done` / `engine.baidu.cancel` / `engine.baidu.error`，数据含 `instanceId`、`mode`、`from`、`to`、`chars`、`bytes`、`items`、耗时与错误码。
- `engine.*.done` 另带耗时与 `totalTokens`（百度为 `chars`）；`engine.*.error` 只带错误码与耗时；取消为 info。
- 队列记录：`queue.enqueue` / `queue.start` / `queue.done` / `queue.cancel` / `queue.limit` / `queue.retry` / `queue.retry.skip`；批量记录：`batch.request` / `batch.item` / `batch.align`。
- 不记录提示词正文与哈希、页面原文、译文、密钥、请求头/体、完整地址；上游原始错误只保留统一错误码与安全提示。
- 日志失败不影响翻译；不因日志改变错误映射、取消或超时行为。

## 9. 边界情况

- **空文本**：单段返回 `{ text: '', usage: null }`，不发上游请求。
- **空 items**：`translateBatch` 直接返回 `{ usage: null }`。
- **缺密钥**：抛 `TranslateError(CONFIG)`，不触发上游调用；`auth.type = none` 不要求密钥。
- **endpoint 非法**：校验阶段抛 `CONFIG`，不构造请求。
- **主机权限未授权**：抛 `CONFIG`，不构造/发送请求。
- **已取消**：调用前 `signal.aborted` 为真时直接抛 `CANCELLED`；流式过程中取消时停止回调并取消 reader。
- **超时**：OpenAI 单段 120 秒、批量 180 秒；百度单段 15 秒、批量 30 秒（均可覆盖）→ 映射为 `NETWORK`。
- **空译文**：OpenAI 单段抛 `OTHER`「引擎返回空译文」，百度同样；批量按段交给 A2 处理。
- **非标准响应**：content 数组、缺少 choices、非法 JSON、非标准事件都按 `OTHER` 失败。
- **批量对齐失败**：已解析段落保留在 `onItem` 与缓存中；缺失/重复/未知/非法行只影响未完成段。
- **百度语言**：`from` 只允许 `auto` / `en`，`to` 不允许 `auto`；`ja → jp`、`ko → kor`；不支持的语言在发请求前失败。
- **百度文本超长**：单段或单批 `q` 超过 4800 UTF-8 字节时 `OTHER`「文本过长」；不拆分单段，切批由 A2 负责。
- **百度无流式**：单段批也没有 `ST_ITEM_DELTA`，只等完整响应。
- **旧实例**：`type: 'deepseek'` 经 `mapLegacyDeepSeek()` 映射，非法 `reasoningEffort` 回退 `off`，不携带 `apiKey`。
- **未知类型**：`type` 既不是 `openai` / `deepseek` 也不是 `baidu` 时抛 `CONFIG`，不发请求。
- **队列不持久化**：Service Worker 重启后 pending/running 丢失，由 A2 的提交超时兜底；页面重连后的续传由 D5 重发未完成段（每次断连最多一次）。
- **队列持凭据**：只在内存使用，不落日志、不进帧、不写存储。
