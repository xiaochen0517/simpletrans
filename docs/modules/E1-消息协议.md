## 1. 职责与边界

- 定义扩展内部的**统一错误码、消息名、端口名与载荷校验辅助**，作为后台、弹窗、设置页与页面注入的协议来源。
- 只定义协议，不实现业务：校验的调用方是 A1（控制面）与 A2（数据面）。
- 页面注入只引用消息名、错误码、失败原因与端口名；不引用密钥、地址或引擎实现。

## 2. 错误码与分类标志

统一错误码（`ERROR_CODES`）与分类标志（`ERROR_FLAGS`）：

| 错误码 | 分类 | retryable | splittable |
| ------ | ---- | :--: | :--: |
| `CONFIG` | 配置（缺密钥/缺引擎/配置无效） | 否 | 否 |
| `AUTH` | 鉴权与额度 | 否 | 否 |
| `RATE_LIMIT` | 限流 | 是 | 否 |
| `NETWORK` | 网络/超时/流中断 | 是 | 否 |
| `BATCH_ALIGN` | 批量对齐 | 否 | 是 |
| `CANCELLED` | 取消 | 否 | 否 |
| `OTHER` | 其它 | 否 | 否 |

辅助：`isKnownCode(code)`、`errorInfo(code)`（未知码回退 `OTHER`，返回 `{ retryable, splittable }`）、`makeError(code, message, reason?)`。`ERROR_FLAGS` 的每个标志项只有 `retryable` 与 `splittable` 两个字段；不提供备用切换。

重试与 QPS 常量在 `src/shared/constants.js`：`RETRY_DELAYS_MS = [1000, 2000]`、`RETRY_JITTER_MS = 250`、`QPS_WINDOW_MS = 1000`。A3 队列按前两者做退避与抖动，A2 用 `QPS_WINDOW_MS` 做百度实例的 1 秒滑动窗口。

## 3. 端口与信封

唯一长连接端口名为 `st-gateway`（`PORT_NAME`），由页面注入主动连接，后台只接受这个端口名与扩展自身的发送方。

- 一次性消息：请求 `{ type, payload? }`，响应 `{ ok: true, data }` 或 `{ ok: false, error: { code, message, reason? } }`。
- 长连接消息：`{ type, payload }`。
- 错误对象统一为 `{ code, message, reason? }`；`code` 来自 `ERROR_CODES`，`reason` 是机器可读的失败原因。

## 4. 消息清单

控制面（一次性消息）：

| 消息 | 方向 | 用途 | 阶段 |
| ---- | ---- | ---- | ---- |
| `ST_LIST_ENGINES` | 设置页 → 后台 | 引擎列表（含实例参数与 `hasKey`，不含密钥与地址） | P2 / P6.2 |
| `ST_TEST_ENGINE` | 设置页 → 后台 | 用已保存配置测试翻译 | P2 |
| `ST_CACHE_STATS` | 设置页 → 后台 | 读取缓存占用（条数、字节、上限） | P5 |
| `ST_CLEAR_CACHE` | 设置页 → 后台 | 清空译文缓存 | P5 |
| `ST_ROUTE` | 弹窗 → 后台 | 命令转发到标签页所有 frame（`start` / `clear` / `status`），并汇总响应 | P6.1 / P12 / P13 |
| `ST_START` | 后台 → 页面注入 | 开始整页任务，带上目标语言与 `traceId`；广播到每个已连接 frame | P6.1 |
| `ST_HOVER_TRIGGER` | 页面注入 → 后台 → 全部 frame | 悬停手势广播，无载荷；后台按来源标签页转发 | P13 |
| `ST_PAGE_SUBMIT` | 页面注入 → 后台 | 统一提交段落（`scope=page/single`），后台校验、计数、逐段日志并回执；按 `sender.frameId` 路由 | P6.1 / P13 |
| `ST_CLEAR` | 后台 → 页面注入 | 广播到每个 frame，清除全部标记与译文并停止滚动增量，汇总清除数量 | P4 / P6.1 |
| `ST_GET_STATUS` | 后台 → 页面注入 | 读取整页会话状态，响应 `{ active }`（任一 frame 开启） | P12 |
| `ST_QUICK_TRANSLATE` | 弹窗 → 后台 | 快速翻译一段文本（临时实例与目标语言），返回纯文本译文 | P11 |
| `ST_GET_SELECTION` | 弹窗 → 后台 | 只读当前活动标签页选中文字，截断到 4000 字符 | P11 |

数据面（`st-gateway`）：

| 消息 | 方向 | 用途 | 阶段 |
| ---- | ---- | ---- | ---- |
| `ST_PING` / `ST_PONG` | 页面 → 后台 / 后台 → 页面 | 握手与心跳 | P2 |
| `ST_TRANSLATE_BATCH` | 页面 → 后台 | 提交一批待译文本 | P2 |
| `ST_ITEM_START` | 后台 → 页面 | 某段开始处理 | P2 |
| `ST_ITEM_DELTA` | 后台 → 页面 | 某段增量文本 | P2 |
| `ST_ITEM_DONE` | 后台 → 页面 | 某段定稿 | P2 |
| `ST_ITEM_ERROR` | 后台 → 页面 | 某段失败 | P2 |
| `ST_BATCH_DONE` | 后台 → 页面 | 整批结束（含整批拒绝） | P2 |
| `ST_CANCEL_BATCH` / `ST_CANCEL_ITEM` | 页面 → 后台 | 取消整批 / 取消单段 | P2 |
| `ST_CLOSE` | 页面 → 后台 | 主动关闭连接 | P2 |
| `ST_LOG_CONFIG` | 后台 → 页面 | 连接建立后下发日志级别 | P3 |
| `ST_CONTENT_CONFIG` | 后台 → 页面 | 连接建立后下发内容配置 `{ hoverShortcut }`；页面只应用第一帧 | P12 |

`ST_BATCH_DONE` 是每批的唯一终态：校验失败、缺密钥、超时、取消、正常完成都会发它。整批拒绝时 `ok: false` 且带 `error`，各计数为 0；正常结束或部分失败时带 `done`、`failed`、`cancelled` 计数。

Q12 结论：不新增 `ST_STOP`（`ST_CLEAR` 已覆盖清除语义）；不新增 `ST_RETRY`，失败段「刷新」复用 `ST_PAGE_SUBMIT(scope='single')`；`ST_GET_STATUS` 在 P12 落地，只返回整页会话是否开启的布尔值，供弹窗单按钮选择动作，不展示进度。`scope='single'` 同时用于悬停单段与失败段「刷新」，两者只是触发入口不同。

`ST_LOG_CONFIG` 与 `ST_CONTENT_CONFIG` 只在每个连接建立后各下发一次；日志记录本身不进入消息通道。所有命令类消息可带可选 `traceId`，当前支持 `ST_TEST_ENGINE`、`ST_QUICK_TRANSLATE`、`ST_GET_SELECTION` 与 `ST_TRANSLATE_BATCH`。

### 4.1 `ST_CLEAR` 与 `ST_GET_STATUS`（P4 / P12）

后台 → 页面注入，一次性消息：

```json
{ "type": "ST_CLEAR", "payload": {} }
{ "type": "ST_GET_STATUS", "payload": { "traceId": "t-…" } }
```

响应：

```json
{ "ok": true, "data": { "removed": 2 } }
{ "ok": true, "data": { "active": true } }
```

- `ST_CLEAR` 清除页面全部标记并停止滚动增量：响应中的 `removed` 为移除的标记数。
- `ST_GET_STATUS` 读取整页会话状态：页面会话处于 `scanning` / `submitting` / `submitted` 时 `active` 为 `true`，`idle` / `error` 为 `false`；没有任务或 DOM 时返回 `active: false`。
- 悬停单段不再经过后台消息：页面手势直接调用任务 `toggle`，结果动作（`submitted` / `hidden` / `submitting` / `no-target` / `failed`）只作为页面内部返回值，不再有 `ST_TOGGLE`。

### 4.2 路由失败原因（P4）

| 阶段 | `reason` | 说明 |
| ---- | -------- | ---- |
| 取活动标签页 | `NO_ACTIVE_TAB` | `tabs.query` 没有返回可用标签页 |
| 页面无接收方且无法补注入 | `INJECTION_FAILED` | `chrome://`、应用商店等不可注入页面，或注入被拒绝 |
| 补注入后仍无接收方 / 通信失败 | `NO_RECEIVER` | 页面脚本未就绪或通信失败，提示刷新 |

这三个原因只用于 A1 路由与日志，不进入批次校验；`code` 统一为 `OTHER`。

### 4.3 缓存消息与域名（P5）

设置页 → 后台，一次性消息：

```json
{ "type": "ST_CACHE_STATS", "payload": {} }
```

响应：

```json
{ "ok": true, "data": { "entries": 1234, "bytes": 12582912, "maxBytes": 1073741824, "maxEntries": 1000000 } }
```

```json
{ "type": "ST_CLEAR_CACHE", "payload": {} }
```

响应：

```json
{ "ok": true, "data": { "cleared": 1234, "freedBytes": 12582912 } }
```

失败统一为 `code: OTHER`，例如清空失败返回 `{ "ok": false, "error": { "code": "OTHER", "message": "清空缓存失败，请稍后重试" } }`。

- 两条消息只接受扩展自身发送方（复用 A1 的发送方校验）；载荷允许空对象，无必填字段。
- 设置页不直接打开缓存数据库，占用与清空都经这两条消息完成。

域名（`MAX_DOMAIN_CHARS = 253`，`normalizeDomain(value)`）：

- 归一规则：去首尾空白 → 转小写 → 去掉末尾的点；结果必须匹配 hostname（若干标签，每段 1–63 字符，只允许字母、数字与连字符），否则返回空串。
- 带协议、端口、路径、查询串、锚点、非法字符或超长的值一律归一为空串。
- 内容侧与网关共用同一函数，保证两侧规则一致；归一结果只作为缓存来源元数据，不参与缓存 key、不参与命中、不进入提示词与日志。

### 4.4 `ST_ROUTE` 与 `ST_START`（P6.1 / P12）

弹窗 → 后台：

```json
{ "type": "ST_ROUTE", "payload": { "command": "start", "traceId": "t-…" } }
{ "type": "ST_ROUTE", "payload": { "command": "clear", "traceId": "t-…" } }
{ "type": "ST_ROUTE", "payload": { "command": "status" } }
```

- `command` 只接受 `start` / `clear` / `status`；其它值返回 `ok: false`、`code: OTHER`、`reason: INVALID_MESSAGE`。
- 复用 A1 的发送方校验；`start` / `clear` 在扩展停用时返回 `code: CONFIG`、message「扩展已停用」；`status` 只查询状态，不读设置、不检查实例。
- 取活动标签页失败返回 `code: OTHER`、`reason: NO_ACTIVE_TAB`；页面不可注入或未就绪的失败原因见 4.2。
- `clear` 转发 `ST_CLEAR`，`start` 转发 `ST_START`，`status` 转发 `ST_GET_STATUS`；后台向该标签页所有已连接 frame 逐帧发送并汇总响应（`start` 相加 `total`、`clear` 相加 `removed`、`status` 取任一 `active`），全部 frame 失败时才返回页面侧错误码。
- `status` 的页面响应为 `{ "ok": true, "data": { "active": true } }`；`active` 为 `false` 时弹窗显示「翻译整页」，为 `true` 时显示「显示原文」。

后台 → 页面注入：

```json
{ "type": "ST_START", "payload": { "targetLang": "zh", "traceId": "t-…" } }
```

- 载荷只有目标语言与可选 `traceId`；页面侧不接收批大小、不接收任务状态。
- 页面异步扫描视口附近段落并提交后回包：

```json
{ "ok": true, "data": { "phase": "submitted", "total": 12 } }
{ "ok": true, "data": { "phase": "idle", "total": 0 } }
{ "ok": true, "data": { "phase": "scanning", "total": 0 } }
{ "ok": true, "data": { "phase": "submitting", "total": 0 } }
```

- `phase` 为 `scanning` / `submitting` / `submitted` / `idle`；`total` 为本次页面会话已成功提交的段落数。
- 首次开始：扫描并提交成功后返回 `phase: 'submitted'` 与 `total`，页面会话开始监听滚动。
- 视口附近没有可译段落：`ok: true`、`phase: 'idle'`、`total: 0`。
- 扫描或首次提交中再次触发：返回当前 `phase` 与 `total`，不重复提交。
- `submitted` 表示页面会话已建立；滚动增量提交不改变该 phase，也不再有额外的 `ST_START` 回包。
- 页面不可用（没有 DOM）返回 `ok: false`、`OTHER`「当前页面不可用，请刷新后重试」；扫描异常返回 `ok: false`、`OTHER`「扫描页面失败，请稍后重试」；提交失败沿用后台返回的错误码与消息。
- 弹窗关闭导致回包失败只记日志，页面任务继续。

### 4.5 `ST_PAGE_SUBMIT`（P6.1）

页面注入 → 后台，一次性消息；悬停单段与整页都使用它，用 `scope` 区分：

```json
{
  "type": "ST_PAGE_SUBMIT",
  "payload": {
    "requestId": "s-…",
    "traceId": "t-…",
    "scope": "page",
    "targetLang": "zh",
    "domain": "example.com",
    "viewport": { "width": 1280, "height": 800 },
    "paragraphs": [
      { "index": 0, "hostId": "h3f9c2a-1", "text": "Hello" },
      { "index": 1, "hostId": "h3f9c2a-2", "text": "World" }
    ]
  }
}
```

- `scope`：`page`（整页首次或滚动增量）或 `single`（悬停单段）；缺省按 `page`。
- `paragraphs` 按本次提交的文档顺序排列，`index` 从 0 连续递增，只用于日志与人工核对；`hostId` 为页面内唯一段落 id（`h<实例标记>-<序号>`），同时作为结果帧 `itemId`。
- 每段只有 `index` / `hostId` / `text`；不携带上下文，段落对象中的其它字段被忽略。
- `domain` 为当前页面 `location.hostname`（`normalizeDomain()` 归一），不参与校验拒绝；`viewport` 只用于日志定位。
- 载荷不得包含地址、密钥、模型等禁止字段；原文以外的页面数据（HTML、选择器列表、完整 URL）不上报。

校验顺序：载荷为对象 → `scope`（`page` / `single`）→ `requestId`（可选，≤64）→ `paragraphs` 为数组且长度 1–`MAX_PAGE_PARAGRAPHS`（5000）→ `scope='single'` 时长度必须为 1 → 每段为对象、`text` 为非空字符串、`hostId` ≤ 64 字符 → 禁止字段。

| 检查 | 规则 | `reason` |
| ---- | ---- | -------- |
| 载荷 | 非空普通对象 | `INVALID_MESSAGE` |
| `scope` | 可选；`page` / `single` | `INVALID_MESSAGE` |
| `requestId` | 可选字符串，≤ 64 字符 | `INVALID_MESSAGE` |
| `paragraphs` | 数组，1–5000 段；`single` 时恰好 1 段 | `INVALID_ITEMS` |
| 段内容 | 普通对象且 `text` 为非空字符串 | `INVALID_ITEMS` / `EMPTY_TEXT` |
| 段标识 | 可选字符串，≤ 64 字符 | `INVALID_ITEMS` |
| 其它段落字段 | 不校验、不拒绝（含旧的 `context`） | — |
| 字段白名单 | 不得出现 `apiKey`/`key`/`baseUrl`/`url`/`headers`/`model`/`instance`/`engineId` | `FORBIDDEN_FIELD` |

- 失败返回 `{ ok: false, error: { code, message, reason? } }`，`code` 统一为 `OTHER`。
- 成功回执 `{ ok: true, data: { accepted: true, requestId, scope, paragraphs, chars } }`：表示提交已创建并转交 A2；翻译结果与失败通过 `ST_ITEM_*` / `ST_BATCH_DONE` 帧逐段回传，回执本身不携带译文。
- 后台记录一条 `page.received`（`scope`、`requestId`、段数、字符数、`tabId`、`frameId`），再按数组顺序为每段记录一条 debug 级 `page.item`（`index`、`hostId`、`textLength`）；不记录原文、上下文与完整 URL。
- 只接受扩展自身发送方；路由时使用 `sender.tab.id + sender.frameId`（`frameId` 缺省 `0`），同一标签页下 `requestId` 重复的提交被拒绝（`DUPLICATE_REQUEST`）；悬停单段可与页面会话并行。

百度实例另含 `baseUrl`（固定 `https://fanyi-api.baidu.com`）、`model: "general"`、`batchSize`、`batchMaxChars`、`maxConcurrency`、`qps`（1–100 整数，默认 1），不含 `endpoint` / `auth` / `headers` / `params` / `systemPrompt` / `quickPrompt`；OpenAI 实例不返回 `qps`。不支持的类型返回 `typeLabel: "不支持"`、`kind: "unsupported"`、`hasKey: false`、`permission: "unsupported"`。

- 不创建默认实例；列表为空时返回空数组。
- 百度 `qps` 由 `validateInstance` 校验为 1–100 整数；`normalizeInstance` 对缺失值补默认 1、越界值夹取到范围内；`toPublicInstance` 只对百度返回 `qps`。`configVersion` 仍为 2。

- 模型名允许自由输入；测试翻译若模型无效，由上游返回 `AUTH` / `OTHER`，设置页不维护模型白名单。

  "type": "ST_QUICK_TRANSLATE",

    "text": "serendipity",

成功响应：

```json
{
  "ok": true,
  "data": {
    "text": "/ˌserənˈdɪpəti/\nn. 意外发现珍奇事物的本领；机缘巧合；\nWe met by pure serendipity. 我们纯属机缘巧合地相遇。\nThe discovery was a happy serendipity. 这个发现是一次幸运的意外。",

      "preset": "deepseek",

      "kind": "llm"
    }
  }

```

- 载荷只接受 `text` / `targetLang?` / `instanceId?` / `traceId?`。
- `text` 非空且 ≤ 4000 字符；`targetLang` 须受支持，省略时取 `settings.targetLang`；`instanceId` 省略时回退当前实例（再退回第一个实例）。
- 指定实例必须存在、类型受支持、配置有效、已启用、凭据完整与 endpoint 已授权；错误码为 `CONFIG`，提示包含「实例不存在 / 已停用 / 缺少密钥 / 未授权域名」。
- OpenAI 兼容实例使用实例的 `quickPrompt`（缺失或非法回退默认模板）以 `mode='quick'` 调用 A3；百度实例不使用提示词。

`ST_GET_SELECTION` 载荷为 `{ traceId? }`；响应为：

```json
{ "ok": true, "data": { "text": "选中文字", "truncated": false } }
```

- A1 查询当前活动标签页，用 `chrome.scripting.executeScript({ target, func })` 只读 `window.getSelection().toString()`；`trim()` 后超过 4000 字符时截断并置 `truncated: true`。
- 没有活动标签页、页面不可注入（`chrome://`、扩展页、PDF 等）或没有选中文字时返回 `{ text: "", truncated: false }`，不向弹窗报错。
- 不写 DOM、不注入内容脚本、不持久化；日志只记长度、截断标记与来源域名。

禁止字段：两条消息都不接受 `apiKey` / `baseUrl` / `headers` / `model` / `instance` 等字段，出现即 `FORBIDDEN_FIELD`。

### 4.8 `ST_HOVER_TRIGGER`（P13）

页面注入 → 后台（一次性消息，无载荷）：

```json
{ "type": "ST_HOVER_TRIGGER" }
```

- 任意 frame 的悬停手势触发后发送；A1 校验发送方为扩展自身且 `sender.tab.id` 存在，然后向该标签页全部 frame 广播同名消息（`chrome.tabs.sendMessage(tabId, …)`），返回 `{ ok: true, data: { forwarded: true } }`。
- 每个 frame 收到广播后只对 D2 的当前宿主动作：指针在该 frame 内时宿主存在并提交/隐藏，其余 frame 宿主为 `null`，直接忽略。
- 没有来源标签页时返回 `code: OTHER`、`reason: NO_ACTIVE_TAB`；广播失败返回 `reason: NO_RECEIVER`，页面侧在发送失败时回退本 frame 本地处理。
- 消息不携带坐标、文本、段落 id 或标签页 id，后台只做校验与转发。

## 5. 批次请求与响应帧

```json
{
  "type": "ST_TRANSLATE_BATCH",
  "payload": {
    "requestId": "b-1750000000-1",
    "domain": "example.com",
    "targetLang": "zh",
    "context": "页面标题（可选）",
    "items": [{ "itemId": "i0", "text": "Hello world", "context": "上一段（可选）" }]
  }
}
```

`domain` 是批次级可选字段：内容侧带当前页面 `location.hostname`，网关用 `normalizeDomain()` 归一后只写入缓存元数据；缺失或非法按空串处理，不阻断翻译。

P6.1 起整页与悬停单段都走 `ST_PAGE_SUBMIT`（见 4.5），数据面批次不再由 D5 发送，保留用于协议兼容、测试与后续批量执行；协议仍支持每批 1–12 段、批次级 `targetLang` 与 `context`、每段 `context`（≤400 字符，批内合计 ≤1200 字符）。

页面结果帧按下表回传：`itemId` 即段落 id，`requestId` 即 `ST_PAGE_SUBMIT` 的 `requestId`；结果帧经 D4 长连接下发，页面侧协议不变。

| 帧 | payload |
| -- | ------- |
| `ST_ITEM_START` | `{ requestId, itemId }` |
| `ST_ITEM_DELTA` | `{ requestId, itemId, delta }` |
| `ST_ITEM_DONE` | `{ requestId, itemId, text, usage }` |
| `ST_ITEM_ERROR` | `{ requestId, itemId, code, message, reason? }` |
| `ST_BATCH_DONE` | `{ requestId, ok, done, failed, cancelled, error? }` |
| `ST_PING` | `{ sentAt }` |
| `ST_PONG` | `{ sentAt, receivedAt }` |
| `ST_LOG_CONFIG` | `{ level }`（`debug` / `info` / `warn` / `error` / `off`） |

整批通过后即使单段失败，也发 `ST_BATCH_DONE`（`ok: false`）并带计数，不再带整批 `error`。批超时结算的段可能没有对应的 `ST_ITEM_START`，客户端必须按 `requestId`/`itemId` 结算。

`payload` 还可带可选 `traceId`（非空字符串 ≤ 64），只用于日志关联；`ST_TEST_ENGINE` 同样支持。

## 6. 批次校验与失败原因

校验顺序：消息类型 → `requestId` → 重复批次 → `items` → 段字段 → 长度与上下文 → 禁止字段 → 目标语言 → 在途批数 → 引擎与密钥。任一失败整批拒绝，不产生上游请求。

| 检查 | 规则 | `reason` |
| ---- | ---- | -------- |
| 消息类型 | 已知类型且 `payload` 为对象 | `INVALID_MESSAGE` |
| `requestId` | 非空字符串 ≤ 64 | `INVALID_REQUEST_ID` |
| 重复批次 | 同端口在途批次不得重名 | `DUPLICATE_REQUEST` |
| `items` | 数组，1–12 段 | `INVALID_ITEMS` |
| `itemId` | 非空字符串 ≤ 64 | `INVALID_ITEMS` |
| 重复段 | 批内 `itemId` 唯一 | `DUPLICATE_ITEM_ID` |
| `text` | 字符串，trim 后非空 | `EMPTY_TEXT` |
| 单段长度 | ≤ 4000 字符 | `TEXT_TOO_LONG` |
| 批总量 | 各段合计 ≤ 12000 字符 | `BATCH_TOO_LARGE` |
| 上下文 | 段 ≤ 400，批合计 ≤ 1200 | `CONTEXT_TOO_LONG` |
| 字段白名单 | 不得出现 `apiKey`/`key`/`baseUrl`/`url`/`headers`/`model`/`instance`/`engineId` | `FORBIDDEN_FIELD` |
| 目标语言 | 仅接受 A3 支持的语言 | `UNSUPPORTED_LANG` |
| 在途批数 | 每端口 ≤ 4 | `TOO_MANY_INFLIGHT` |
| 批超时 | 整批 > 180 秒 | `BATCH_TIMEOUT`（`NETWORK`） |
| `traceId` | 可选；存在时非空字符串 ≤ 64，非法值忽略、不阻断请求 | — |
| `domain` | 可选；缺失、非字符串、超长或非法字符按空串处理，不阻断请求 | — |

桥本地失败原因：`DISCONNECTED`、`NOT_CONNECTED`（`NETWORK`）、`EXTENSION_INVALIDATED`（`OTHER`）。

## 7. 边界情况

- 未知消息名：一次性消息返回 `ok: false`，长连接回一帧 `ST_BATCH_DONE`（`ok: false`，`INVALID_MESSAGE`）。
- `ST_PING` 不进入批次表、不占并发名额、不写存储。
- `requestId` 只有在同端口**在途**时才算重复；批次结束后可复用。
- 禁止字段检查覆盖嵌套对象，页面文本只作为字符串处理。
- `ST_LOG_CONFIG` 每连接只下发一次，不进入批次表、不占并发、不写存储；重连后新连接重发。级别非法时归一为 `info`，不断开连接。
- `ST_CLEAR` / `ST_GET_STATUS` / `ST_START` 只接受扩展自身发送方；`ST_PAGE_SUBMIT` 由 A1 校验发送方与载荷；页面注入忽略其它上下文的消息，不响应未知类型。
- 页面注入未运行：后台先 `insertCSS` 再 `executeScript`，然后重发一次；仍无接收方时返回 `NO_RECEIVER`，不复重试。
- `ST_PAGE_SUBMIT` 走一次性消息，不依赖 `st-gateway` 在途状态；页面同时最多一条在途，扫描或首次提交中再次触发只返回当前状态。
- `ST_START` 的提交由页面异步完成，消息通道保持到整页提交结束再回包；`ST_GET_STATUS` 与 `ST_CLEAR` 同步回包。
- `traceId` 只用于日志关联，不参与校验、缓存 key、去重或业务判断；非法值忽略。
- `domain` 只作为缓存来源元数据：不参与校验拒绝、不参与缓存 key、不参与命中判断；旧页面不带 `domain` 时按空串处理。
- 两条缓存消息的存储异常统一归为 `OTHER`，不新增错误码与失败原因。
