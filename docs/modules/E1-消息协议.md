| 日期 | 结论 |

源码：`src/shared/protocol.js`。

## 1. 职责与边界

- 定义扩展内部的**统一错误码与错误分类标志**，作为后台、弹窗、设置页与页面注入的协议来源。
- P1 只落错误码；消息名（控制面 `ST_LIST_ENGINES`/`ST_TEST_ENGINE` 与数据面消息）及报文格式在 P2 落地。

## 2. 错误码与分类标志

统一错误码（`ERROR_CODES`）与分类标志（`ERROR_FLAGS`）：

| 错误码 | 分类 | retryable | splittable | fallbackable |
| ------ | ---- | :--: | :--: | :--: |
| `CONFIG` | 配置（缺密钥/缺引擎/配置无效） | 否 | 否 | 是 |
| `AUTH` | 鉴权与额度 | 否 | 否 | 是 |
| `RATE_LIMIT` | 限流 | 是 | 否 | 是（重试仍失败后） |
| `NETWORK` | 网络/超时/流中断 | 是 | 否 | 否 |
| `BATCH_ALIGN` | 批量对齐 | 否 | 是 | 否 |
| `CANCELLED` | 取消 | 否 | 否 | 否 |
| `OTHER` | 其它 | 否 | 否 | 视情况 |

辅助：`isKnownCode(code)`、`errorInfo(code)`（未知码回退 `OTHER`）。

P1 只实现 DeepSeek 会产生的映射（`CONFIG`/`AUTH`/`RATE_LIMIT`/`NETWORK`/`OTHER`）；`BATCH_ALIGN`、`CANCELLED` 的枚举先定义，映射由 P2/P8 落地。

## 3. 消息清单（P2 补）

消息名与方向、报文格式见 [项目架构](../项目架构.md) 4.6；架构 Q12 的三个补充名（`ST_STOP`、`ST_RETRY`、`ST_GET_STATUS`）在 P2 落地协议时一并补进 4.6 清单。P1 不落任何消息名。
