## 1. 职责与边界

- 定义扩展内部的**统一错误码、消息名、端口名与载荷校验辅助**，作为后台、弹窗、设置页与页面注入的协议来源。
- 只定义协议，不实现业务：校验的调用方是 A1（控制面）与 A2（数据面）。
- 页面注入只引用消息名、错误码、失败原因与端口名；不引用密钥、地址或引擎实现。

## 2. 错误码与分类标志

统一错误码（`ERROR_CODES`）与分类标志（`ERROR_FLAGS`）：

| 错误码 | 分类 | retryable | splittable | fallbackable |
| ------ | ---- | :--: | :--: | :--: |
| `CONFIG` | 配置（缺密钥/缺引擎/配置无效） | 否 | 否 | 是 |
| `AUTH` | 鉴权与额度 | 否 | 否 | 是 |
| `RATE_LIMIT` | 限流 | 是 | 否 | 是（重试仍失败后） |
| `NETWORK` | 网络/超时/流中断 | 是 | 否 | 否 |
| `BATCH_ALIGN` | 批量对齐 | 否 | 是 | 否 |
| `CANCELLED` | 取消 | 否 | 否 | 否 |
| `OTHER` | 其它 | 否 | 否 | 视情况 |

辅助：`isKnownCode(code)`、`errorInfo(code)`（未知码回退 `OTHER`）、`makeError(code, message, reason?)`。

## 3. 端口与信封

唯一长连接端口名为 `st-gateway`（`PORT_NAME`），由页面注入主动连接，后台只接受这个端口名与扩展自身的发送方。

- 一次性消息：请求 `{ type, payload? }`，响应 `{ ok: true, data }` 或 `{ ok: false, error: { code, message, reason? } }`。
- 长连接消息：`{ type, payload }`。
- 错误对象统一为 `{ code, message, reason? }`；`code` 来自 `ERROR_CODES`，`reason` 是机器可读的失败原因。

## 4. 消息清单

控制面（一次性消息）：

| 消息 | 方向 | 用途 | 阶段 |
| ---- | ---- | ---- | ---- |
| `ST_LIST_ENGINES` | 设置页 → 后台 | 引擎列表（只含 `hasKey`，不含密钥） | P2 |
| `ST_TEST_ENGINE` | 设置页 → 后台 | 用已保存配置测试翻译 | P2 |
| `ST_CACHE_STATS` | 设置页 → 后台 | 读取缓存占用（条数、字节、上限） | P5 |
| `ST_CLEAR_CACHE` | 设置页 → 后台 | 清空译文缓存 | P5 |
| `ST_ROUTE` | 弹窗 → 后台 | 命令转发到标签页 | P7 |
| `ST_START` | 后台 → 页面注入 | 开始整页任务 | P6/P7 |
| `ST_TOGGLE` | 后台 → 页面注入 | 切换指针所在段落的译文 | P4 |
| `ST_CLEAR` | 后台 → 页面注入 | 清除全部译文并取消在途请求 | P4 |

数据面（`st-gateway`）：

| 消息 | 方向 | 用途 | 阶段 |
| ---- | ---- | ---- | ---- |
| `ST_PING` / `ST_PONG` | 页面 → 后台 / 后台 → 页面 | 握手与心跳 | P2 |
| `ST_TRANSLATE_BATCH` | 页面 → 后台 | 提交一批待译文本 | P2 |
| `ST_ITEM_START` | 后台 → 页面 | 某段开始处理 | P2 |
| `ST_ITEM_DELTA` | 后台 → 页面 | 某段增量文本 | P2 |
| `ST_ITEM_DONE` | 后台 → 页面 | 某段定稿 | P2 |
| `ST_ITEM_ERROR` | 后台 → 页面 | 某段失败 | P2 |
| `ST_BATCH_DONE` | 后台 → 页面 | 整批结束（含整批拒绝） | P2 |
| `ST_CANCEL_BATCH` / `ST_CANCEL_ITEM` | 页面 → 后台 | 取消整批 / 取消单段 | P2 |
| `ST_CLOSE` | 页面 → 后台 | 主动关闭连接 | P2 |
| `ST_ENGINE_CHANGED` | 后台 → 页面 | 通知已切备用 | P9 |
| `ST_LOG_CONFIG` | 后台 → 页面 | 连接建立后下发日志级别 | P3 |

`ST_BATCH_DONE` 是每批的唯一终态：校验失败、缺密钥、超时、取消、正常完成都会发它。整批拒绝时 `ok: false` 且带 `error`，各计数为 0；正常结束或部分失败时带 `done`、`failed`、`cancelled` 计数。

Q12 结论：不新增 `ST_STOP`（`ST_CLEAR` 已覆盖清除语义）；`ST_RETRY` 在 P9、`ST_GET_STATUS` 在 P7 落地。

`ST_LOG_CONFIG` 只在每个连接建立后下发一次；日志记录本身不进入消息通道。所有命令类消息可带可选 `traceId`，P3 先支持 `ST_TEST_ENGINE` 与 `ST_TRANSLATE_BATCH`。

### 4.1 `ST_TOGGLE` 与 `ST_CLEAR`（P4）

后台 → 页面注入，一次性消息：

```json
{ "type": "ST_TOGGLE", "payload": { "traceId": "t-…" } }
{ "type": "ST_CLEAR", "payload": {} }
```

响应：

```json
{ "ok": true, "data": { "action": "translating" } }
{ "ok": true, "data": { "removed": 2, "cancelled": 1 } }
```

`ST_TOGGLE` 的 `action`：

| 值 | 含义 |
| -- | ---- |
| `translating` | 已显示加载态并提交批次（含连接建立前的排队） |
| `hidden` | 已有译文，本次移除了该段译文 |
| `cancelled` | 加载中再次触发，取消请求并移除显示 |
| `no-target` | 指针不在可译段落上 |
| `too-long` | 段落超过单段上限，本地提示，不发请求 |

- 指针不在可译段落上返回 `ok: true` 与 `no-target`，不当作错误。
- 页面注入未就绪（没有 DOM）时返回 `ok: false`，`message` 为「当前页面不可用，请刷新后重试」。
- `ST_CLEAR` 的响应只用于后台日志与 P7；P4 没有 UI 入口。

### 4.2 路由失败原因（P4）

| 阶段 | `reason` | 说明 |
| ---- | -------- | ---- |
| 取活动标签页 | `NO_ACTIVE_TAB` | `tabs.query` 没有返回可用标签页 |
| 页面无接收方且无法补注入 | `INJECTION_FAILED` | `chrome://`、应用商店等不可注入页面，或注入被拒绝 |
| 补注入后仍无接收方 / 通信失败 | `NO_RECEIVER` | 页面脚本未就绪或通信失败，提示刷新 |

这三个原因只用于 A1 路由与日志，不进入批次校验；`code` 统一为 `OTHER`。

### 4.3 缓存消息与域名（P5）

设置页 → 后台，一次性消息：

```json
{ "type": "ST_CACHE_STATS", "payload": {} }
```

响应：

```json
{ "ok": true, "data": { "entries": 1234, "bytes": 12582912, "maxBytes": 1073741824, "maxEntries": 1000000 } }
```

```json
{ "type": "ST_CLEAR_CACHE", "payload": {} }
```

响应：

```json
{ "ok": true, "data": { "cleared": 1234, "freedBytes": 12582912 } }
```

失败统一为 `code: OTHER`，例如清空失败返回 `{ "ok": false, "error": { "code": "OTHER", "message": "清空缓存失败，请稍后重试" } }`。

- 两条消息只接受扩展自身发送方（复用 A1 的发送方校验）；载荷允许空对象，无必填字段。
- 设置页不直接打开缓存数据库，占用与清空都经这两条消息完成。

域名（`MAX_DOMAIN_CHARS = 253`，`normalizeDomain(value)`）：

- 归一规则：去首尾空白 → 转小写 → 去掉末尾的点；结果必须匹配 hostname（若干标签，每段 1–63 字符，只允许字母、数字与连字符），否则返回空串。
- 带协议、端口、路径、查询串、锚点、非法字符或超长的值一律归一为空串。
- 内容侧与网关共用同一函数，保证两侧规则一致；归一结果只作为缓存来源元数据，不参与缓存 key、不参与命中、不进入提示词与日志。

## 5. 批次请求与响应帧

```json
{
  "type": "ST_TRANSLATE_BATCH",
  "payload": {
    "requestId": "b-1750000000-1",
    "domain": "example.com",
    "targetLang": "zh",
    "context": "页面标题（可选）",
    "items": [{ "itemId": "i0", "text": "Hello world", "context": "上一段（可选）" }]
  }
}
```

`domain` 是批次级可选字段：内容侧带当前页面 `location.hostname`，网关用 `normalizeDomain()` 归一后只写入缓存元数据；缺失或非法按空串处理，不阻断翻译。

| 帧 | payload |
| -- | ------- |
| `ST_ITEM_START` | `{ requestId, itemId }` |
| `ST_ITEM_DELTA` | `{ requestId, itemId, delta }` |
| `ST_ITEM_DONE` | `{ requestId, itemId, text, usage }` |
| `ST_ITEM_ERROR` | `{ requestId, itemId, code, message, reason? }` |
| `ST_BATCH_DONE` | `{ requestId, ok, done, failed, cancelled, error? }` |
| `ST_PING` | `{ sentAt }` |
| `ST_PONG` | `{ sentAt, receivedAt }` |
| `ST_LOG_CONFIG` | `{ level }`（`debug` / `info` / `warn` / `error` / `off`） |

整批通过后即使单段失败，也发 `ST_BATCH_DONE`（`ok: false`）并带计数，不再带整批 `error`。批超时结算的段可能没有对应的 `ST_ITEM_START`，客户端必须按 `requestId`/`itemId` 结算。

`payload` 还可带可选 `traceId`（非空字符串 ≤ 64），只用于日志关联；`ST_TEST_ENGINE` 同样支持。

## 6. 批次校验与失败原因

校验顺序：消息类型 → `requestId` → 重复批次 → `items` → 段字段 → 长度与上下文 → 禁止字段 → 目标语言 → 在途批数 → 引擎与密钥。任一失败整批拒绝，不产生上游请求。

| 检查 | 规则 | `reason` |
| ---- | ---- | -------- |
| 消息类型 | 已知类型且 `payload` 为对象 | `INVALID_MESSAGE` |
| `requestId` | 非空字符串 ≤ 64 | `INVALID_REQUEST_ID` |
| 重复批次 | 同端口在途批次不得重名 | `DUPLICATE_REQUEST` |
| `items` | 数组，1–12 段 | `INVALID_ITEMS` |
| `itemId` | 非空字符串 ≤ 64 | `INVALID_ITEMS` |
| 重复段 | 批内 `itemId` 唯一 | `DUPLICATE_ITEM_ID` |
| `text` | 字符串，trim 后非空 | `EMPTY_TEXT` |
| 单段长度 | ≤ 4000 字符 | `TEXT_TOO_LONG` |
| 批总量 | 各段合计 ≤ 12000 字符 | `BATCH_TOO_LARGE` |
| 上下文 | 段 ≤ 400，批合计 ≤ 1200 | `CONTEXT_TOO_LONG` |
| 字段白名单 | 不得出现 `apiKey`/`key`/`baseUrl`/`url`/`headers`/`model`/`instance`/`engineId` | `FORBIDDEN_FIELD` |
| 目标语言 | 仅接受 A3 支持的语言 | `UNSUPPORTED_LANG` |
| 在途批数 | 每端口 ≤ 4 | `TOO_MANY_INFLIGHT` |
| 批超时 | 整批 > 180 秒 | `BATCH_TIMEOUT`（`NETWORK`） |
| `traceId` | 可选；存在时非空字符串 ≤ 64，非法值忽略、不阻断请求 | — |
| `domain` | 可选；缺失、非字符串、超长或非法字符按空串处理，不阻断请求 | — |

桥本地失败原因：`DISCONNECTED`、`NOT_CONNECTED`（`NETWORK`）、`EXTENSION_INVALIDATED`（`OTHER`）。

## 7. 边界情况

- 未知消息名：一次性消息返回 `ok: false`，长连接回一帧 `ST_BATCH_DONE`（`ok: false`，`INVALID_MESSAGE`）。
- `ST_PING` 不进入批次表、不占并发名额、不写存储。
- `requestId` 只有在同端口**在途**时才算重复；批次结束后可复用。
- 禁止字段检查覆盖嵌套对象，页面文本只作为字符串处理。
- `ST_LOG_CONFIG` 每连接只下发一次，不进入批次表、不占并发、不写存储；重连后新连接重发。级别非法时归一为 `info`，不断开连接。
- `ST_TOGGLE` / `ST_CLEAR` 只接受扩展自身发送方；页面注入忽略其它上下文的消息，不响应未知类型。
- 页面注入未运行：后台先 `insertCSS` 再 `executeScript`，然后重发一次；仍无接收方时返回 `NO_RECEIVER`，不复重试。
- 补注入后命令可能早于 `st-gateway` 连接建立：页面注入先显示加载态，把尚未发出的批次排队到连接建立后提交；排队超过 5 秒或连接永久关闭时显示失败。
- `traceId` 只用于日志关联，不参与校验、缓存 key、去重或业务判断；非法值忽略。
- `domain` 只作为缓存来源元数据：不参与校验拒绝、不参与缓存 key、不参与命中判断；旧页面不带 `domain` 时按空串处理。
- 两条缓存消息的存储异常统一归为 `OTHER`，不新增错误码与失败原因。
