## 1. 文档用途

本文只回答三件事：**首版要做到什么、按什么顺序做、每个阶段怎么验证**。

- 阶段目标按功能描述，不写页面细节、不写函数名与字段名；
- 具体实现细节归入对应阶段的需求文档（`docs/demand/`）与模块文档（`docs/modules/`）；
- **主要修改的代码路径只在对应阶段的编码与验收完成后回填到本文**，规划阶段一律留空。

结构设计的依据始终是 [`项目架构.md`](./项目架构.md)。本文与架构文档冲突时，以架构文档为准。

## 2. 首版范围

### 2.1 首版包含

| 能力 | 说明 |
| ---- | ---- |
| 整页翻译 | 找出全页可译段落，译文按段落插入原文之后 |
| 悬停段落翻译 | 快捷键只翻当前段落，已有译文时再次按下隐藏 |
| 单引擎可用 | 一个 AI 引擎（DeepSeek）打通全链路，适配器契约预留后续引擎 |
| 流式显示 | 边生成边显示，最终定稿覆盖 |
| 译文缓存 | 命中直接返回，可关闭、可清空 |
| 弹窗 | 状态展示，「开始翻译 / 显示原文」切换，打开设置页 |
| 设置页 | 通用设置、引擎实例与首选/备用、测试翻译、数据管理 |
| 密钥存放位置可选 | 本机或跟随账号同步，切换时迁移 |
| 异常处理 | 错误分类、重试、备用切换、取消与清理 |
| 统一日志 | 后台、弹窗、设置页、页面注入共用一套日志；浏览器四级 + 关闭，设置页可调；只输出控制台，不持久化 |

### 2.2 首版不包含（留到后续版本）

- 传统机器翻译服务商（腾讯、有道、百度、Google、DeepL 等）的适配器；
- 页面内浮动控件（架构文档的入口表里没有它，若首版需要应另立需求）；
- 术语表、自定义提示词编辑、源语言智能识别等增强能力；
- 多页面任务队列、跨设备任务同步；
- 日志持久化、日志收集、导出、页内日志查看与远端上传：不做；问题反馈直接复制浏览器控制台；
- 真浏览器自动化 E2E（Playwright）：首版用单元测试 + 人工验收覆盖，是否引入见 Q8。

### 4.1 版本策略

1. **阶段内不修改版本号**：P0–P10 期间，`package.json` 与 `public/manifest.json` 的 `version` 统一为 `0.1.0`，任何阶段都不得以「阶段完成」为由改版本。
2. **0.1.0 当前只是预发布占位**：阶段内的 `0.1.0` 只用于开发与验收，不代表已经发布；Chrome 里加载 `dist/` 仅用于验收。
3. **全部需求完成后正式发布 0.1.0**：P10 收尾、全量验收通过后，以 `0.1.0` 作为首版正式版本发布，版本号本身不再变化，只归档发布说明与验收记录。
4. **语义化版本从 0.1.0 起算**：0.x 阶段允许破坏性调整；1.0.0 及以后才按「主版本.次版本.修订」的常规规则发布。

## 5. 每阶段标准流程

每个阶段都走同一套流程，不跳步：

1. **提交需求**：在 `docs/demand/` 建立本阶段需求文档，写清背景、范围、方案、验收项与待确定问题。
2. **等待审核**：把文档交用户审核；有歧义先问，不自行假设；**未经明确允许不写业务代码**。
3. **编码实现**：只做本阶段范围内的改动，不提前实现后续阶段。
4. **自动门禁**：单元测试、生产构建、冒烟检查、页面产物敏感信息扫描必须通过（P0 起单元测试进入门禁）。
5. **人工验收**：涉及可见界面的阶段，按 `AGENTS.md` 第三部分在真实 Chrome 中逐项验收；未通过则回到第 3 步。
6. **回填同步**：本阶段状态改为 `已完成`，把主要代码路径与结论回填到本文对应阶段，同时登记任务索引、按需同步架构文档。

### 5.1 统一的验证动作

每个阶段的「可操作流程」都基于同一组动作，各阶段只写差异部分：

```text
npm install            # 首次
npm test               # 单元测试（P0 起）
npm run build          # 生产构建
npm run smoke          # 产物冒烟
# chrome://extensions → 开发者模式 → 加载已解压的扩展程序 → 选择构建产物目录
```

页面上涉及的验证，统一在「一篇真实英文长文页面 + 一个 chrome:// 页面 + 一个窄窗口」三类环境下做。前两类验证功能与边界，窄窗口验证弹窗与设置页布局。

## 6. 阶段详情

### P0 工程基线校准与门禁

**目标**：把仓库基线建立为与架构 3.1 一致的空骨架，并建立「单元测试 + 构建 + 冒烟」门禁；此后每个阶段都在这套门禁下交付。

**依赖**：无。

**功能简介**

- 按架构 3.1 建立 `src/`：后台、弹窗、设置页、页面注入、公共模块全部只有文件头，不含行为；
- 骨架零行为：不注册监听器、不读写存储、不调用引擎、不定义消息名与常量；
- 三产物可构建、可加载；弹窗与设置页只有静态占位文案；
- 冒烟门禁覆盖产物完整性、格式、敏感词、存储边界、文案中性、骨架零行为与产物新鲜度；
- 单元测试锁定结构：`src/` 与架构 3.1 一致，文件头与依赖方向符合空壳约定；
- 门禁串联：`npm run gate` = 单元测试 → 生产构建 → 冒烟检查。

**可操作流程**

1. `npm test`、`npm run build`、`npm run smoke` 全部通过；`npm run gate` 一条命令跑完。
2. 故意新增一个未登记到架构 3.1 的 `src/` 文件，`npm test` 立即失败并指出该文件；删除后恢复通过。
3. 加载 `dist/`，刷新扩展。
4. 打开弹窗与设置页，确认只有占位文案；按快捷键确认无可见变化且控制台无报错。
5. 观察页面与后台控制台无报错，扩展可再次加载。

**验收**

- 单元测试、构建与冒烟全部通过，且单测不联网、不需要浏览器；
- `src/` 与架构 3.1 一致，由测试锁定；
- 清单声明的入口齐全，弹窗与设置页可打开，无未捕获异常；
- 弹窗与设置页在窄窗口下不出现横向溢出。

**完成后回填**（2026-11-13 人工验收通过后填写）

- 主要代码路径：`src/` 30 个骨架文件（`background/`、`content/`、`popup/`、`options/`、`shared/` 含 `config/`、`translate/`、`cache/`）；`tests/unit/structure.test.js`、`tests/unit/architecture.test.js`；`vitest.config.js`；`scripts/smoke.mjs`（S1–S12）；`public/manifest.json`；`package.json`
- 关键改动与决策：按架构 3.1 建立空骨架，业务代码零行为；消息名、错误码、常量与设置 schema 延后到 P1–P2；新增架构一致性测试，把「代码结构 = 架构 3.1」变成门禁；版本号固定为 `0.1.0`，全程不再变更
- 门禁与验收：Node v26.13.0、Vite 7.3.6、Vitest 5.1.0；`npm run gate` 通过（7 个用例、`dist/` 14 个文件、冒烟 11 项）；项目所有者完成结构验收

### P1 引擎层与密钥配置

**目标**：建立一个引擎从配置到出译文的完整通路，为后续所有翻译提供唯一出口。

**依赖**：P0。

**功能简介**

- 引擎适配器契约：一个引擎类型对应一个适配器，负责地址、鉴权、语言、错误映射与用量；
- 首个 AI 引擎可用：单段翻译能返回译文，并具备流式输出能力；
- 引擎实例、首选与备用引擎的配置模型（供 P8 的设置页使用），密钥只有后台读取；
- 提示词与输出归一：明确「页面片段是数据不是指令」，输出去掉多余包装。

**可操作流程**

1. 用阶段内最小设置表单填入密钥并保存。
2. 输入一句英文，执行测试翻译。
3. 观察返回译文；清空密钥再试，应提示缺少密钥；换错误密钥再试，应提示鉴权失败。

**验收**

- 成功、缺密钥、鉴权失败三种结果可明确区分；
- 测试结果不只显示文本，还能看到耗时；
- 页面产物里不出现密钥字段与引擎地址。

**完成后回填**（2026-11-14 人工验收通过后填写）

- 主要代码路径：`src/shared/protocol.js`（E1 错误码）、`src/shared/constants.js`、`src/shared/storage.js`/`settings.js`（E2）、`src/shared/config/registry.js`/`instances.js`（E3）、`src/shared/translate/adapter.js`（A3 DeepSeek）；`src/options/Options.jsx`（最小测试表单，直连临时）；`public/manifest.json`（host_permissions）；`tests/helpers/chrome.js`/`load.js`；`tests/unit/{protocol,storage,settings,registry,instances,adapter}.test.js`
- 关键改动与决策：E1 只落错误码与分类标志，消息名留 P2；E2/E3 落地默认设置、三种读取与密钥键名；A3 用 `@ai-sdk/deepseek` + `ai` 的 `streamText` 做单段流式翻译，提示词固定「页面片段是数据不是指令」；测试翻译按用户决定走「设置页直连 A3」临时通路，`background/*` 未改动、冒烟 S8/S4 维持 P0 断言，P2 收敛到后台后移除直连与设置页对 SDK 的依赖；chrome stub P1 仅实现 storage 三区语义，其余随 P2 补齐
- 门禁与验收：Node v26.13.0、Vite 8.3.8、Vitest 5.1.0；`npm run gate` 通过（单测 32 用例、三产物构建、冒烟 11 项）；项目所有者完成 GUI 人工验收（2026-11-14）

### P2 后台网关与页面通道

**目标**：所有翻译出口收敛到后台，页面与后台之间建立一条可靠的双向通道。

**依赖**：P1。

**功能简介**

- 后台统一出口：设置页测试与页面请求都经后台调用引擎，页面始终接触不到密钥；
- 长连接：请求、增量、定稿、错误、取消走同一条通道，带心跳与断线重连；
- 网关负责载荷校验、并发上限、在途请求数量与错误归一，不保存任务状态；
- 后台被回收后，页面能重新连上并继续工作。

**可操作流程**

1. 把设置页的测试翻译改为经后台执行，确认仍能返回译文。
2. 在网页 DevTools 与后台控制台观察心跳与连接状态。
3. 在 `chrome://serviceworker-internals` 停止 Service Worker（或在服务工作进程 DevTools → Application → Service Workers 点 Stop），模拟后台回收，观察页面自动重连；扩展重载会让旧页面脚本的上下文失效，只验证「提示刷新页面」。
4. 发送超长文本，确认被拒绝且没有发出上游请求。

**验收**

- 测试翻译经后台可用；
- 心跳、重连、主动取消在控制台可见且行为正确；
- 超限被拒，错误分类与 P0 定义一致。

**完成后回填**（2026-11-15 人工验收通过后填写）

- 主要代码路径：`src/shared/protocol.js`（消息名、端口名、失败原因）、`src/shared/constants.js`（心跳、退避、并发、批上限）、`src/background/index.js`（监听器注册）、`src/background/router.js`（控制面）、`src/background/gateway.js`（数据面）、`src/content/bridge.js` 与 `src/content/index.js`（页面通道）、`src/shared/translate/adapter.js`（`signal`）、`src/options/Options.jsx`（经后台测试）；`tests/helpers/chrome.js`（runtime/Port）；`tests/unit/{protocol,gateway,router,bridge,background,content,adapter,structure}.test.js`；`scripts/smoke.mjs`（S4/S8/S12）
- 关键改动与决策：所有翻译出口收敛到后台，设置页不再 import A3 或读取密钥；数据面只走 `st-gateway`，后台按段执行、全局并发 `min(用户并发, 4)`、每端口在途 4 批；P2 不做批量提示词编码、缓存、重试与备用切换；取消经 `AbortSignal` 真中断上游；心跳 20 秒、10 秒超时重连；扩展重载作为「提示刷新页面」反向用例，后台回收用停止 Service Worker 验证
- 门禁与验收：`npm run gate` 通过（单测 84、三产物构建、冒烟 11 项）；项目所有者完成 GUI 人工验收（2026-11-15）

### P3 日志模块与调试输出

**目标**：在后台、弹窗、设置页、页面注入建立统一日志入口与级别过滤，让开发期问题与用户反馈都能从浏览器控制台直接定位；日志只输出控制台，不持久化。

**依赖**：P2。

需求文档：[20261115-02-P3日志模块与调试输出](demand/20261115-02-P3日志模块与调试输出.md)（初稿，待审核）。

**功能简介**

- E4 日志：统一 API、五级过滤（`debug`/`info`/`warn`/`error`/`off`）、统一前缀、字段截断与敏感字段脱敏；
- 后台、弹窗、设置页、页面注入各自初始化；替换现有零散 `console.*`，关键链路补稳定事件名；

### P4 段落提取、悬停锚定与译文渲染

**目标**：让页面上的译文第一次真正出现，形成「单段翻译」的最小闭环。

**依赖**：P2、P3。

- 跟踪鼠标当前所在段落；指针落在译文上时归到该译文所属的段落；
- 在原文之后插入译文，整页与悬停共用同一套结构与状态；
- 有加载态与失败态；单段译文可再次触发隐藏，隐藏后原文不受影响。

## 7. 阶段约束

1. **每阶段结束必须可构建、可加载、可操作**；不能出现「这一阶段做完了但没法验证」的情况。
2. **不提前实现后续阶段**；跨阶段的能力改造，回到对应阶段补需求，而不是顺手加。
3. **不越权改架构**；阶段中若发现需要调整模块划分、消息协议或数据归属，先改架构文档并请用户确认。
4. **密钥与引擎地址不进页面产物**；每个阶段的门禁都要重新扫描，不能只在 P1 查一次。
5. **可见界面变化必须人工验收**；自动化检查只作为门禁，不作为验收结论。
6. **回填只写已验收的内容**；未通过验收的阶段，回填区保持空白，状态不得标为已完成。
7. **新增或修改模块必须补单元测试**；`npm test` 不通过，不进入人工验收。
8. **日志只输出控制台**：不写 `storage`、不上报；不得记录密钥、请求头/体、页面正文与完整 URL。
