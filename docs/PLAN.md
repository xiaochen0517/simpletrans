## 1. 文档用途

本文只回答三件事：**首版要做到什么、按什么顺序做、每个阶段怎么验证**。

- 阶段目标按功能描述，不写页面细节、不写函数名与字段名；
- 具体实现细节归入对应阶段的需求文档（`docs/demand/`）与模块文档（`docs/modules/`）；
- **主要修改的代码路径只在对应阶段的编码与验收完成后回填到本文**，规划阶段一律留空。

结构设计的依据始终是 [`项目架构.md`](./项目架构.md)。本文与架构文档冲突时，以架构文档为准。

## 2. 首版范围

### 2.1 首版包含

| 能力 | 说明 |
| ---- | ---- |
| 整页翻译 | 找出全页可译段落，译文按段落插入原文之后 |
| 悬停段落翻译 | 快捷键只翻当前段落，已有译文时再次按下隐藏 |
| 单引擎可用 | 一个 AI 引擎（DeepSeek）打通全链路，适配器契约预留后续引擎 |
| 流式显示 | 边生成边显示，最终定稿覆盖 |
| 译文缓存 | 命中直接返回，可关闭、可清空 |
| 弹窗 | 状态展示，「开始翻译 / 显示原文」切换，打开设置页 |
| 设置页 | 通用设置、引擎实例与首选/备用、测试翻译、数据管理 |
| 密钥存放位置可选 | 本机或跟随账号同步，切换时迁移 |
| 异常处理 | 错误分类、重试、备用切换、取消与清理 |
| 统一日志 | 后台、弹窗、设置页、页面注入共用一套日志；浏览器四级 + 关闭，设置页可调；只输出控制台，不持久化 |
| 翻译测试页 | 扩展内固定英文内容页，弹窗一键打开，用于稳定的人工翻译测试 |

### 2.2 首版不包含（留到后续版本）

- 传统机器翻译服务商（腾讯、有道、百度、Google、DeepL 等）的适配器；
- 页面内浮动控件（架构文档的入口表里没有它，若首版需要应另立需求）；
- 术语表、自定义提示词编辑、源语言智能识别等增强能力；
- 多页面任务队列、跨设备任务同步；
- 日志持久化、日志收集、导出、页内日志查看与远端上传：不做；问题反馈直接复制浏览器控制台；
- 真浏览器自动化 E2E（Playwright）：首版用单元测试 + 人工验收覆盖，是否引入见 Q8。

### 4.1 版本策略

1. **阶段内不修改版本号**：P0–P10 期间，`package.json` 与 `public/manifest.json` 的 `version` 统一为 `0.1.0`，任何阶段都不得以「阶段完成」为由改版本。
2. **0.1.0 当前只是预发布占位**：阶段内的 `0.1.0` 只用于开发与验收，不代表已经发布；Chrome 里加载 `dist/` 仅用于验收。
3. **全部需求完成后正式发布 0.1.0**：P10 收尾、全量验收通过后，以 `0.1.0` 作为首版正式版本发布，版本号本身不再变化，只归档发布说明与验收记录。
4. **语义化版本从 0.1.0 起算**：0.x 阶段允许破坏性调整；1.0.0 及以后才按「主版本.次版本.修订」的常规规则发布。

## 5. 每阶段标准流程

每个阶段都走同一套流程，不跳步：

1. **提交需求**：在 `docs/demand/` 建立本阶段需求文档，写清背景、范围、方案、验收项与待确定问题。
2. **等待审核**：把文档交用户审核；有歧义先问，不自行假设；**未经明确允许不写业务代码**。
3. **编码实现**：只做本阶段范围内的改动，不提前实现后续阶段。
4. **自动门禁**：单元测试、生产构建、冒烟检查、页面产物敏感信息扫描必须通过（P0 起单元测试进入门禁）。
5. **人工验收**：涉及可见界面的阶段，按 `AGENTS.md` 第三部分在真实 Chrome 中逐项验收；未通过则回到第 3 步。
6. **回填同步**：本阶段状态改为 `已完成`，把主要代码路径与结论回填到本文对应阶段，同时登记任务索引、按需同步架构文档。

### 5.1 统一的验证动作

每个阶段的「可操作流程」都基于同一组动作，各阶段只写差异部分：

```text
npm install            # 首次
npm test               # 单元测试（P0 起）
npm run build          # 生产构建
npm run smoke          # 产物冒烟
# chrome://extensions → 开发者模式 → 加载已解压的扩展程序 → 选择构建产物目录
```

页面上涉及的验证，统一在「一篇真实英文长文页面 + 一个 chrome:// 页面 + 一个窄窗口」三类环境下做。前两类验证功能与边界，窄窗口验证弹窗与设置页布局。

### P4 段落提取、悬停锚定与译文渲染

**目标**：让页面上的译文第一次真正出现，形成「单段翻译」的最小闭环。

**依赖**：P2、P3。

需求文档：[20261116-01-P4段落提取悬停锚定与译文渲染](demand/20261116-01-P4段落提取悬停锚定与译文渲染.md)（已审核；人工验收通过，已完成 2026-11-16）。

**功能简介**

- 找出页面可翻译的文字宿主，跳过脚本、样式、表单值控件、隐藏内容与已翻译内容；文本归一后交给后台，相同文本的去重由 P5 缓存承担；
- 跟踪鼠标当前所在宿主；指针落在译文上时归到该译文所属的宿主；

3. 再次按 Ctrl，该宿主译文隐藏；再按一次可重新翻译。
4. 把鼠标停在 input / textarea / 可编辑区、折叠隐藏内容上，确认不会误翻；按钮、链接、代码应正常翻译。

- 译文颜色、字体、字号、行高随宿主，不破坏原有布局，滚动与缩放后仍正常；

### P5 译文缓存

**目标**：重复内容不再重复请求，同时保证缓存不会返回错误结果。

**依赖**：P3、P4。

需求文档：[20261116-02-P5译文缓存](demand/20261116-02-P5译文缓存.md)（已审核；人工验收通过，已完成 2026-11-16）。

**功能简介**

- 按「引擎、模型、语言、提示词版本、上下文、原文」判断是否可复用；
- 命中直接返回，不调用引擎；失败与取消不写缓存；
- 页面每次触发都提交后台，同文本段落由缓存命中，不再重复调用上游；
- 缓存存 IndexedDB，配额不设限，应用层使用 1 GiB / 100 万条保守上限；只在后台读写，跨标签页共享；超限按最近最少使用淘汰；
- 缓存元数据记录来源域名，查询与命中仍只按缓存 key；内容侧请求携带域名；
- 设置页显示缓存占用，可关闭缓存与清空缓存；详细管理留 P8。

**可操作流程**

1. 翻译一段，记录有加载过程的感受。
2. 刷新页面后再翻译同一段，应几乎立即出现；设置页的缓存占用增加。
3. 在设置页清空缓存后再翻，恢复请求过程，占用归零。
4. 改目标语言后再翻同一段，不应复用旧语言的结果（当前仅支持 `zh`，GUI 验收方式见需求文档 Q9，待确认）。

**验收**

- 命中、清空、语言变化三种情况都符合预期；
- 设置页占用随翻译写入增加，命中不重复增加，清空后归零；
- 域名写入缓存元数据，但不影响命中与清空全部缓存；
- 关闭缓存后不再命中；
- 相同文本段落与隐藏后再次触发由缓存命中，只调用一次上游；

> 各子任务的范围、设计与验收以对应子文档为准；本节保留 P6 整体目标与最终回填。

**功能简介**

- 视口附近取段，滚动时按 200ms 防抖增量补交新段落；
- 按实例的 `batchMaxChars` / `batchSize` 以段为单位切批，翻译队列按 `maxConcurrency` 控制同时在途批次数；
- 同 key 段落共用一个结果；多段批一次上游请求，单段批保留流式；
- 段落状态依次推进，单段失败只影响该段，任务最终进入完成或部分失败；
- 重复触发只更新参数，不新建任务、不产生重复译文。

**可操作流程**

1. 打开长文网页，触发整页翻译。
2. 观察视口内段落先出译文，滚动后剩余段落继续补齐。
3. 中断网络翻几段，再恢复网络，观察失败段落与其余段落的差异。
4. 翻译进行中再次触发整页翻译，确认没有重复任务与重复译文。

**验收**

- 顺序、并发、失败隔离、去重都符合预期；
- 长页面不卡顿、不出现整页空白或乱序译文；
- 任务能自然结束，不残留进行中状态。

**完成后回填**（2026-11-16 人工验收通过后填写）

- 主要代码路径：`src/shared/translate/queue.js`（A3 FIFO 队列、并发、取消与统计）、`src/shared/translate/batch.js`（JSONL 编码/解析/对齐）、`src/shared/translate/adapter.js`（`translateBatch`）、`src/background/gateway.js`（分组、切批、入队、按段写缓存与 fan-out、取消与超时）、`src/content/task.js`（结果帧状态机）；`tests/unit/queue.test.js`、`batch.test.js` 与 `adapter/gateway/router` 测试扩展
- 关键改动与决策：批次以 P6.3 的唯一 key group 为单位切分（`batchSize` / `batchMaxChars` 先到先切、不拆段、超长段单独成批）；批次进入 A3 全局 FIFO 队列，按实例 `maxConcurrency` 限制同时在途批次数，每批只占 1 个队列名额并复用一个全局上游名额；单段批走 `translate` 保留逐字流式，多段批走一次 JSONL `translateBatch`、按 group id 对齐并逐段回帧；按段写缓存与 fan-out，不等整批结束；批量空译文只失败该段，对齐失败保留已解析段、其余标 `BATCH_ALIGN`；取消/超时/断线按 group 摘除 job，job 无 group 时 abort；队列等待计入 180 秒提交超时

## 7. 阶段约束

1. **每阶段结束必须可构建、可加载、可操作**；不能出现「这一阶段做完了但没法验证」的情况。
2. **不提前实现后续阶段**；跨阶段的能力改造，回到对应阶段补需求，而不是顺手加。
3. **不越权改架构**；阶段中若发现需要调整模块划分、消息协议或数据归属，先改架构文档并请用户确认。
4. **密钥与引擎地址不进页面产物**；每个阶段的门禁都要重新扫描，不能只在 P1 查一次。
5. **可见界面变化必须人工验收**；自动化检查只作为门禁，不作为验收结论。
6. **回填只写已验收的内容**；未通过验收的阶段，回填区保持空白，状态不得标为已完成。
7. **新增或修改模块必须补单元测试**；`npm test` 不通过，不进入人工验收。
8. **日志只输出控制台**：不写 `storage`、不上报；不得记录密钥、请求头/体、页面正文与完整 URL。
